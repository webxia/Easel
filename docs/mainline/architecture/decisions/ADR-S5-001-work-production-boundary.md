# ADR-S5-001 · 作品确认与生产执行边界

- **状态：ACCEPTED — 仅限本 ADR 列出的逻辑职责与交接原则；不是技术选型冻结或实施验收。** 2026-10-16。
- **关联需求**：V2-EXP-005～008、012～013、019～021、024～027、031～034。
- **接受依据**：用户先认可主线和职责，再认可完整视频案例与衔接方式，并要求按此方向整理 S5、暂不锁定框架。原稿混合的存储/框架推荐已移出决定范围，保留在架构候选与研究资料中。
- **证据**：[S4 差距清单](../../history/v2/11_REQUIREMENT_GAP_MAP.md)、[逻辑架构基线](../domain.md)、[认可的案例](../../history/v2/13_PRODUCTION_WALKTHROUGH.md)。案例为纸面推演，V1 局部成功不证明 V2 自主闭环。

## 已确认决定

1. 现有六维画像就是主人设；频道与导演关系按 S4，不新增重复 Creator 档案。
2. 完整创作方案与授权绑定指定修订；确认后在范围内自主执行，仅实质变更、授权缺口或无法继续的问题交用户决定。
3. 创作方案、真实素材上的制作规划、实际成片上的局部修订分层衔接；阶段以真实产物推进，保持同一作品及可追溯版本。导演在阶段内有创作自由，不套固定脚本套路。
4. 模型负责叙事、视听、选材、语义判断和修订建议；程序负责身份、版本、状态、权限、次数、引用与恢复；用户负责最终接受。
5. 新作品有一个有效生产执行负责方。Web/Chat/Skill 是入口或能力，不能绕过作品授权形成第二条收费制作链。该原则不规定进程数量或框架。
6. 沿用 Easel 基础，迁入 S4 指定的 V1 素材能力；不整体搬回旧生产执行链、阶段预算、历史数据或凭证。具体源文件适配与验收见架构 §10。
7. 用户额度仅计实际生图/生视频提交；配音不纳入。已有成果优先复用；未知提交保留原操作身份并核实，不盲重发或随运行重置消耗。
8. 局部修订按实际影响处理，保护未修改内容和历史版本；重渲染不等于重新生成。实质扩大影响或新增生成按已确认说明/授权方式处理。
9. 技术检查、实际视听检查、可审阅首版和用户接受区分留证；接受绑定实际版本，保存内容库，不自动发布或沿用旧授权到新作品。

## 未决定的技术实现

本 ADR 不选择 LangGraph、DBOS、Temporal 或自研编排，不选择 SQLite/数据库表、Hypit/FFmpeg/其他渲染器、模型或供应商，也不批准新的多 Agent 部署。逻辑模块名称不等于固定代码目录、服务或接口。

框架检查点不能成为第二套用户授权/次数权威；外部提交与本地写入的窗口仍需核实处理，不能承诺跨服务恰好一次。实际隔离、恢复、素材迁入、局部保护和媒体能力验证见[架构 §12](../domain.md#12-集中的待验证清单与决策边界)，均尚未按新主线验证通过。

## 后续决策与变更

技术验证失败时调整实现，不静默改写已确认产品目标或职责。若确需改变本 ADR，说明新证据、影响和替代方案并请求变更决定；不能将框架默认行为当作用户新授权。业务实施、付费生产、旧数据迁移和上游合并不在本次文档整理范围内。
