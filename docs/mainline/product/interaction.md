# 对话式创作交互

状态：**当前已确认交互边界**。行为要求见[需求](requirements.md)，对应实现与限制见[架构导读](../architecture/overview.md)，具名部署/验收见[状态](../project/status.md)。本页不把早期设计分镜作为当前界面截图。

## 入口与依据

沿用 Easel 对话入口，视频创作、创建导演、创建频道是三条业务管线。导演是创作依据与职责，不是另起一个聊天人格。频道/导演目录提供选择、具体版本和来源，进入后仍在同一对话澄清、确认与查看结果。

临时创作允许不选画像/频道，但须明确导演；有画像作品与创建频道的要求见合同。不把其他画像的经历或默认记忆带入临时作品。频道定位、导演版本、声音及交付设置应明确来源；后续默认值变化不改写本片冻结依据。

## 讨论、确认、制作、交付

1. 讨论形成有版本和来源的创作依据；聊天承诺不代表Plan已生成或已确认。
2. 展示实际完整方案、范围及必要授权。具体提案经真人回合确认后，服务端绑定真实版本办理命令；模型候选和系统结果事件不授予权限。
3. 确认后尽可能自主执行供料、声音、编辑、渲染与适用检查。真正的范围变化、缺权限、Rights或UNKNOWN才进入必要决定；不增加逐阶段审批。
4. 进度和结果取自持久业务状态。等待结束、停止回答、关闭页面不等于取消生产；当前同步等待预算到期后后台原任务可继续，原会话结果订阅的交付条件见实现导读。
5. 可播放产物回到原作品对应对话；技术成功、语义检查、Creator亲自审阅分别呈现。manual模式的needs_fix可能表示未自动全审，不能虚构具体缺陷或冒充语义PASS。
6. Creator可接受或给出局部修改意见。保护原版和未改部分；越出冻结范围时按合同重新确认。接受作品不自动发布、不自动保存长期偏好。

## 创建、恢复与长期保存

频道创建可不创建空Work；参考分析与导演接受保留真实范围，visual-only不能冒充完整音视频理解。参考素材Rights未知不代表可重剪或复用原声。

跨会话续作必须明确关联真实Work和允许依据；不复制任意会话私有历史。聊天、提案、执行回合与Work/Plan/Run的身份各自核验，UNKNOWN不得靠新建对话重发。

长期Profile/偏好写回展示具体内容，由用户单独确认，不能用一次成片接受推断保存授权。发布与归因的未接通部分仍是需求/候选，不宣称完整闭环已实现。

早期分镜、双Agent方案、A1～A10实验与历次交互修订完整保留在[交互演进原文](interaction.md)；其中已替代部署方式仅供追溯。细粒度接口、字段和版本规则唯一维护在[合同](../architecture/contracts.md)。
