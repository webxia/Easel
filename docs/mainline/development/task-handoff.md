# 任务接手、验收与交接约定

本页维护任务交接所需的信息与检查清单；开发/Bug流程、任务归属、授权、持续推进及Git规则统一引用[工程规范](engineering.md)，真实场景另按[E2E规范](testing.md)。不另设固定修复轮数、机器JSON协议或逐步审批。

需求分流与从设计到最终交付的顺序见[工程规范§2.4～§2.5](engineering.md#24-自然语言需求进入与授权判断)，本页只维护交接检查。

## 开工检查

1. 确认用户目标、授权、可观察验收点、范围外事项；读取[状态](../project/status.md)核对生产断点，并按本次用户目标定位对应Task；待评审方案从[任务索引](../project/tasks/README.md)进入，不能承接生产Task的开发/部署授权。核对Task的阶段、授权来源和停止点，阶段转换依工程§2.4记录。旧阶段卡的“当前”“下一步”和一次性授权只属于原轮次。
2. 核对分支、HEAD、Dirty及未跟踪资料；核对依赖的真实产物，不以卡片状态代替交付。不覆盖原有outputs、Profile或无关改动。依赖未满足时只做合法调查，不假报完成。
3. 按需读需求、合同、源码和测试。Markdown链接相对所在文档解析，命令和普通源码路径未特别声明时相对仓库根；旧卡标注“新建”的文件可能已存在，先核对实现再决定修改。合同变更按工程规范评估，不另创同义接口或成功空壳。

## 验证与可移交证据

- 命令从仓库根与受测环境执行，避免机器路径硬编码。测试随负责模块放入现有测试布局：生产域通常在 `tests/production/`，前端Node测试在 `tests/frontend/`，技能沿各自已有目录；不把阶段任务的目录限定当全仓规定。命令见[工程入口](engineering.md#3-官方已有工程入口在对应场景使用)，按实际脚本选择，不能假设存在npm test。
- 使用临时根/库、许可媒体及fake服务，不初始化或清空用户运行库。所需测试尚不存在时补相应验证，不能借此跳过验收；无真实调用授权时完成合法离线部分并保留真实项NOT_TESTED。
- 依赖兼容以当前 `pyproject.toml` 和CI矩阵核对；不得静默提高最低版本、开启云追踪或迁入机器绑定parser。历史Python 3.10/3.12用例是证据，不代替当前平台覆盖。缺服务须明确不可用，fake输出不算真实合格。
- 记录实际HEAD与相关Dirty、输入/环境、命令、结果、未测平台/服务以及CI对应SHA。零收集或全部skip不能算该目标通过；实现、接线、适用正反例与回归、明确错误及文档按本任务完成条件核对。修复后的后续依赖/用户可见交付与研发接管情况，按[E2E取证与收口要求](testing.md#四首次失败取证归因低成本复现)记录；自主稳定性须沿[固定版本验证](testing.md#固定版本的自主稳定性验证)另有证据。验收层次依[工程§5](engineering.md#5-三类验收与优化口径)，不能拼接不同版本的局部成功证明完整自主通过。

## 断点与收口

使用[Task模板](templates/TASK.md)记录目标、范围、依据、实际结果、未闭合风险及唯一下一动作。跨窗口须留下父任务剩余验收；真实运行的身份索引、最后非幂等操作、在途/UNKNOWN及合法恢复方式按[E2E检查点](testing.md#六唯一最新断点与完成条件)记录，私有原文不入库。

Task记录实施结果，运行轮次保留首次失败，[状态](../project/status.md)只汇总当前入口，[候选池](../project/backlog.md)登记非当期事项。Bug和子项是否完成按[工程§2.2](engineering.md#22-复用现有-task调试发现-bug-后回到开发规范)判断；不能以子项完成关闭父任务。提交、推送、PR和保护分支完全按[工程§6](engineering.md#6-git-fork官方同步与成果推送已确认工作规范)，本页不另授予Git权限。

## 回退与成果保护

代码回退和数据回退分开评估；保留有效成果和失败证据，不以删outputs/画像或降低需求换PASS。新schema保留备份与向前修复策略，不随意降级用户库。停用受控生产入口应保留原Web、聊天和内容库；已有未知副作用须按原身份核验。
