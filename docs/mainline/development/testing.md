# 调试与真实 Web E2E 规范

> **CURRENT：本文件仅定义调试、真实 Web E2E 和恢复的特殊规则，不定义新开发流程、任务或授权。** 当前事项、实际状态以[CURRENT_STATE](../project/status.md)和[实施任务包](../project/tasks/S6_IMPLEMENTATION_PLAN.md)为准；凡确认需要改代码（包括调试发现的 Bug），统一按[工程开发规范](engineering.md)分析、设计、实施、验证，再回原场景复验。历史 V1.2～V1.4 的执行通道切换、浏览器寿命和事故留在 Git 及具名记录中，**不作为当前并行规范**。
>
> 正式 Web 的历史参考地址是 http://127.0.0.1:7860/；可访问或 HTTP 200 不等于实际已加载受测代码。软件测试、隔离模拟、真实生产和人工审片必须分开记录。

## 一、一个 Task，两种模式

- **DEBUG（取证、归因与定向复验）**：以**当前活动 Task 的验收目标**为准，保存首次失败和可复现证据；先分清工具、环境、测试、业务或 UNKNOWN。确证代码 Bug 后按[统一开发流程](engineering.md)处理必要修复与关联回归，按授权部署后回原场景**定向复验**，继续父 Task 剩余验收。失败不是自动新建 Task 或请求用户再次说“继续”的理由。
- **ACCEPTANCE（固定版本独立验收）**：冻结 HEAD、Dirty 增量、构建和实际服务、测试输入及权限；按 G0～G6 正式路径验收，不边修代码边称“一次通过”。失败保存原判定和证据，回 DEBUG；修复完成后另按授权发起新轮或可合法定向复验。
- **执行者与工具**：Codex 是默认研发执行者，按已有权限使用浏览器、终端、现有测试、回执和源码。ChatGPT/WebCodex 等是可选操作通道，不构成第二套主控或必须部署的控制器；研发 Task 与 Easel 产品 Work/Plan/Run/Operation 的职责不能混淆。

## 二、用户指令与既有合同有偏差时的处理

在正式 Web/真实 Provider 场景中，涉及**确认方案、权限、费用、Rights、必需素材／允许降级、撤销和不可逆操作**的指令变化，先核对原用户决定、当前冻结合同和操作副作用。发生实质不一致时依[统一开发规范 §2.3](engineering.md)给出证据、影响、推荐与一个具体问题，暂停相关写操作；用户明确确认后更新原 Task／必要合同再继续。普通同范围技术诊断或授权内修复不逐项反复请示，不能为了减少交互绕过正式确认、扩大付费或修改 Creator 接受状态。
## 三、真实 Web G0～G6 判据

| Gate | 必须取得的可观察证据 |
|---|---|
| G0 | 正式 Web 已加载目标版本；本轮所需画像/频道/导演/声音设置及Conversation合法就绪；无画像临时创作、静音等合法模式不强加不适用配置 |
| G1 | 原对话讨论创建/绑定唯一 Work |
| G2 | 真实 Planning 生成完整、身份合法、持久化并可核对的 Plan |
| G3 | 原对话按正确版本正式确认 Plan；口头接受或 HTTP 200 不够 |
| G4 | 在Rights/费用范围完成真实素材、适用音轨/配音、时间线、渲染及适用QC；静音等模式不为过Gate新增声音 |
| G5 | 与本轮 Work/Plan/Run 对应的**真实可播放 MP4**回传同一 Conversation |
| G6 | Creator亲自审片并明确接受或提出修改；反馈须如实记录，提出修改不算CREATOR_ACCEPTED，代理不得代签 |

每 Gate 用 `PASS / FAIL / BLOCKED / PARTIAL / NOT_TESTED`；技术结果单列 `SOFTWARE_PASS / BUILD_PASS / DEPLOY_PASS / REAL_PRODUCTION_PASS / CREATOR_ACCEPTED`。没执行不算 PASS，没有有效自动听审或人工证据不能声称语义质量通过。

## 四、首次失败取证、归因、低成本复现

1. **首次证据**：找到第一个真正阻断 Gate 的异常，保留当时 Web 可见内容、后端回执、Plan/Run/Operation 状态与副作用；HTTP/SSE 成功不代表业务完成。运行 IDs、用户画像、完整原始模型响应、媒体和凭证只保存在本机私有目录。
2. **分类再修**：先区分 `DEBUG_RECOVERY / ENVIRONMENT / TEST_BUG / PRODUCT_BUG / UNKNOWN`，再按根 AGENTS 判断 `SAFETY / CURRENT_BLOCKER / LATER / RESEARCH`。浏览器过期或工具失联不是自动的产品 Bug。
3. **先离线回放**：使用已留存的真实失败回执、`pytest` 正反例、既有隔离 Web/Worker/FFmpeg 夹具。回放已保存响应不等于再调用模型；真实模型的不确定性需要另外的有界、具名样本验证。
4. **转回开发规范实施修复**：确定真实代码／测试 Bug 后，将首次证据链接到**现有活动 Task**，按[统一开发流程](engineering.md)完成必要原因分析、方案取舍、代码与正反回归；影响模块较多也不自动新增项目。不降低合同、Rights/UNKNOWN 防护或删除断言；没有新证据先补观测，不盲目叠补丁。
5. **返回父 Task 原场景验收**：定向复验优先在原 Work 合法入口复用已成功 Plan/素材/声音及 Operation；修复单测 PASS 不能关闭原 E2E Task。记录已完成 Gate、剩余缺陷及实际成果。仅在 Task 要求固定版本独立验收且当前授权覆盖新作品/新费用时开新轮；旧 FAIL 保留。

可直接复用 `python -m pytest`、`node --test tests/frontend/*.test.mjs` 与 `scripts/validate_conversation_a5.py --root <临时目录>`。后者用假模型和合成媒体，不能充当真实 E2E PASS。

## 五、业务恢复和安全禁令

- 先核实 Git/Dirty/构建/实际进程、原 Conversation/Work/Plan/Run/Operation 及在途/UNKNOWN；Codex Job 完成、浏览器列表为空或工具超时不说明产品操作未执行。
- 原浏览器丢失，若现有正式 UI 能经合法身份恢复原对话且副作用可核对，可继续；否则先只读核清旧轮操作、安全收口为 `ENVIRONMENT_INTERRUPTED`，再按授权选择是否重新创建独立轮。
- `pending`、网络断开、取消及 UNKNOWN 不允许盲目重发或“清理数据库后重试”；禁止 SQL 业务状态写入、伪造回执、复制 token/localStorage、后台 API 写入冒充 Web E2E。后端 API 单独调试须标为 `DIAGNOSTIC_API`，不与 G0～G6 混用。
- 付费/媒体生成、真实服务重启、删除数据、外部发布、修改业务范围均需要当次可核实授权；历史授权不能因工具切换默认为无限续费或重发。
- 工具寿命按当前浏览器/执行器现状核对，不把某一历史 WebCodex 版本的 30 分钟/4 小时期限当成所有 Codex 浏览器规则。权限明确拒绝不得换工具绕过。

## 六、唯一最新断点与完成条件

每轮真实独立 E2E 在[运行记录目录](../project/tasks/runs/)以 `YYYY-MM-DD-web-e2e-NN.md` 保存**首次失败及真实场景回执**，文首仅一个 **CURRENT CHECKPOINT**；运行过程与复验附具名证据，不覆盖旧 FAIL，Bug 分析/方案/软件结果回写原活动 Task 而非复制另一份开发日志。断点至少包含：任务和原验收目标、授权、源码/Dirty/实际部署、G0～G6、原业务私有 ID 索引、最后非幂等操作/副作用、UNKNOWN/在途、合法恢复方式以及**父 Task 剩余验收和唯一下一动作**。

**停止**：目标证据齐备并等待 Creator 审片；需要用户明确修改方案或授权；涉及安全、权限、未定副作用或无合法恢复入口。工具调用完成不是任务完成，目标已达成也不得为“继续优化”自动扩范围。

具体 S7 的 01～08 检查项只在[实施任务包](../project/tasks/S6_IMPLEMENTATION_PLAN.md)维护，本文件不复制临时阶段排程及每次工具切换指令。

## 七、历史经验的诊断落点

以下是首次失败取证时的检查提示，不新增Gate、重试预算或独立任务。完整案例及原证据见[H1～H5复盘](../history/research/development-debugging-task-integration-2026-10-23.md#71-具名历史案例与本次设计约束)。

| 现象 | 首先核对的边界 |
|---|---|
| Planning长期失败、模型响应成功却无合法Plan | 输入与消费者投影是否丢失替代许可/否定条件，模型输出、结构合同与程序合并中哪一步首先失败；不先归因渲染器或堆Prompt/Gate |
| 用户口头同意但未制作 | 是否有展示过的提案、正式答复及持久确认；待答提案不自动证明事务Bug |
| 素材请求成功但无法制作 | 请求成功→有候选→可下载→Rights合法→用途匹配→持久绑定分别核对；缺素材不自动等于权限故障，不绑定无关候选凑PASS |
| 短SFX越界、恢复后引用丢失、FFmpeg报错 | 对照真实源长、格式/滤镜链、缓存身份及同Work/Run持久引用；按首因定向修复，不能全局提高容差或重做已成功配音/素材 |
| 大请求HTTP500、length或工具超时 | 相关性不等于远端根因；核对原Operation、已留存回执和实际业务终态，不靠换模型/Thinking或重复付费试因果 |
| 若干片段或历史轮次通过 | 每项证据绑定版本、模型、样本、人工介入和验收层；不能拼成完整稳定或自主通过 |

本轮长等待回传的经验也按同一边界处理：等待回合正常退场、业务终态回传和可播放成片是三种不同证据；成功回传BGM缺口不代表G4/G5通过。具名来源见[长任务复验02](../project/tasks/runs/2026-10-23-web-e2e-02.md)，不把其中具体耗时设为固定测试期限。
