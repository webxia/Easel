# 调试与真实 Web E2E 规范

本页只规定真实调试的取证、决策和验收；开发、授权与Git沿[工程规范](engineering.md)，当前对象和停止点沿[状态](../project/status.md)及原Task。目标是减少无效修改与重复生产，完成用户可审阅的交付；增加规则、测试数或模型调用不构成改善证据。

## 一、一个 Task，两种模式

- **DEBUG**：定位当前阻断，修复后在授权内沿原场景继续；保留首次失败及研发介入，不为每个报错建卡。
- **ACCEPTANCE**：固定源码/Dirty、实际部署、输入和权限，通过正常产品路径验证。中途改码、改配置或由研发提供技术恢复指令，记为受助完成，不能称自主通过。普通用户确认范围、提供内容和审片不算研发接管；只读取证也不算，除非据此代替产品完成决策。

Codex使用当前合法工具执行；不要求另设主控、独立代理或换浏览器。独立性来自固定版本、未用于修复的输入和可核验结果，不能把同一执行者自检称为独立审核。

## 二、用户指令与既有合同有偏差时的处理

出现方案冲突或素材缺口，按需追踪**用户原话 → 确认Plan → 实际请求 → 校验/审查意见**，找出条件在哪一步丢失或被加严。分清用户硬要求、导演选择、获准替代及阶段授权；建议和抽样不确定性不自动成为硬缺陷。冻结合同确需修改时按[工程§2.3](engineering.md#23-指令偏差先沟通按任务授权连续执行并收口)取得决定，不能静默放宽；授权内普通诊断与修复不重复请示。

## 三、真实 Web G0～G6 判据

| Gate | 可观察证据 |
|---|---|
| G0 | 正式Web已加载目标版本，本轮适用身份/设置合法就绪；HTTP200不足以证明部署 |
| G1 | 原对话创建/绑定唯一Work |
| G2 | 真实Planning产生完整、合法、可核对的持久Plan |
| G3 | 原对话按正确版本正式确认Plan，非仅口头答复 |
| G4 | 在Rights/费用范围完成真实供料、适用声音、时间线、渲染和适用QC |
| G5 | 对应Work/Plan/Run的真实可播放MP4回传同一Conversation |
| G6 | Creator亲自审片并接受或提出修改；提出修改不算接受，代理不得代签 |

完整E2E记录各Gate的 `PASS / FAIL / BLOCKED / PARTIAL / NOT_TESTED`；定向复验只记录涉及项与未覆盖项，不为小修复制整套表。软件、构建、部署、真实生产、Creator接受分别说明。技术解码、播放器播完、模型自评和完整视听质量不是同一证据；无听审能力时明确未测。静音等合法模式不强加不适用配置。

## 四、首次失败取证、归因、低成本复现

**每次下一动作先回答：它要排除哪个解释，什么结果会改变下一步？** 用原Task几行记录即可，不要求独立分析报告。

1. **定位首次偏离，而非复述最后报错。** 从最近正确节点对照实际输入、原始回执、消费者和副作用，区分产品/环境/测试故障、模型或供料限制、正常用户决策与UNKNOWN；再按根AGENTS确定是否当前阻断。只展开能区分原因的证据，不默认读全历史、重跑全库或逐表备份。
2. **选择能检验假设的最短验证。** 确定性转换、状态和恢复问题优先用原回执及现有隔离测试复现；识图、听感、自然表达和模型是否主动提交不能由脚本答案证明，应查看实际产物，必要时在授权内做有界真实验证。离线回放已足以定位后，不再以增加无关测试推迟原场景验证。
3. **修正已证原因。** 沿工程规范在原Task修复。对照“产生数据 → 保存 → 暂停 → 重载/恢复 → 消费”中本次受影响的边界；检查相邻路径，不穷举全系统。同类报错须先比较失效机制，不能默认旧修复失效，也不能每次只修当前字段。已有测试应能在撤去对应修复时失败；若只检查输出存在或预置PASS，不能证明根因已覆盖。
4. **回到原路径。** 适用回归通过且部署/运行授权具备后，下一动作优先原场景定向复验，验证失败消失、下一依赖执行、用户可见结果及无重复副作用。测试停在排队/running、resume202或MODEL成功，只证明该边界；后续渲染/回传须沿现有集成或真实运行补证，不必给每个单测复制完整制作。新失败从新首因取证，不把它抹成“仍是同一个错误”。

### 继续、换方向与停止的判断

| 当前证据 | 下一动作；避免的无效动作 |
|---|---|
| 回执能稳定触发明确的校验/状态错误 | 本地回放并修对应生产者/消费者，再回原场景；不要付费重问同一个确定性问题 |
| 工具调用成功但没有结果提交 | 数清观察、纠错、提交各轮及预算消耗，检查证据是否复用；不要描述为多次不合格修订或只提高总轮数 |
| 同一失败再次出现，输入/版本/条件均未改变 | 停止该重试，查新证据或改检验假设；有证据的瞬时故障可沿既有有界重试策略，成功仍保留原失败 |
| 改字段、换素材或人工修工程后成功 | 标记局部绕行及条件变化；原合同不满足或原缺陷未复验，不能算通用修复。合法替代不是伪造成功，但必须有原授权及实际效果 |
| 技术通过而实际画面/声音有问题 | 对照真实选用区间、确认要求与检查意见；区分内容冲突、审美偏好和观察不足。身份/时间合法不证明语义正确，模型QC也需反证核查 |
| 无法区分模型能力、请求问题或远端故障 | 明列未证假设，选最小对照；没有判别力或授权就停止付费尝试，不靠换模型、加Prompt/审核碰运气 |

普通工程修复不设统一轮数。停止的是无信息增益或不安全的动作，不是自动终止父任务：可继续只读取证及隔离验证。有新证据且在授权内继续；目标达到、需要用户决定、权限不足、UNKNOWN副作用未明或无合法恢复入口则停止相关业务动作。

可复用 `.venv/bin/python -m pytest tests/production/<相关文件> -q`、`node --test tests/frontend/*.test.mjs` 及 `scripts/validate_conversation_a5.py --root <临时目录>`；按实际环境选命令。脚本模型与合成媒体只证明软件接线/保护，不证明真实创作质量。不得删断言、提高容差、清空素材或放宽Rights/事实/授权来换通过；调整错误测试须说明原预期为何错误及覆盖损失。

## 五、业务恢复和安全禁令

- 恢复前核实实际加载版本、原Conversation/Work/Plan/Run/Operation、最后非幂等动作、在途/UNKNOWN和已有成果。工具超时、浏览器丢失或Job结束不代表业务未执行；先查原结果，不重发未知操作。
- 从原授权核对**保留什么、允许改变什么、剩余缺口、合法恢复入口**。保留成功配音不等于禁止必要补料；不新增AI生成也不等于可任意购买库存。追踪恢复标志到后续任务，禁止擅自扩大限制或清除保护。核对恢复后原稿/声音/已成功回执及调用增量。
- 原浏览器丢失时，可通过正式UI和合法身份恢复原对话；不能恢复则记录环境中断及业务实态，不默认重建作品。禁止SQL业务写入、伪造回执、复制token/localStorage或清库重试。正式后端API诊断单列 `DIAGNOSTIC_API`，不能冒充Web E2E。
- 费用、重启、删除、发布及范围变更依当前持续有效授权；不因工具切换获得新权限，也不因普通失败重复索取已给授权。真实调用不足时完成合法离线部分并明确真实项未测。
- 已有成片在后续修订暂停时，核对它是否仍可找到和播放，同时说明缺陷及修订状态；用户选择保留待修片不等于技术缺陷修复或Creator已接受。

## 六、唯一最新断点与完成条件

复用原Task及[运行记录](../project/tasks/runs/)，每轮仅一个CURRENT CHECKPOINT：**原目标/授权、受测与部署版本、首次失败证据索引、现有产物与副作用、剩余验收、唯一下一动作**。完整原始回执、ID、个人内容与媒体留私有目录，仓库只存脱敏结论和索引。Task写原因/修复/验证，运行记录写真实过程；状态仅在入口变化时更新，不把同一流水复制三遍。

先向用户报告“能拿到什么、仍停在哪里”，再给验证证据。分别判断代码修复、本片交付、自主稳定性；没有执行的项目保留NOT_TESTED，合法用户取舍不混算软件失败或作品完成。

### 固定版本的自主稳定性验证

按原Task目标选少量真实输入与受影响路径，包含未参与修复的样本，预先约定完成条件和费用范围。旧失败必须保留，区分无研发接管交付、受助交付、合法用户决策、未完成；记录接管原因及实际调用/耗时，不凭测试总数或最后一部成功片推导成功率。

规范是否有效，要看它是否改变了下一步决策并获得相应结果：例如避开一次确定无效的重发、捕获旧测试遗漏的恢复路径、推进到真实交付，或纠正虚假PASS。历史回放只能支持规则的适用性，不能证明采用后提高稳定性；规范改动后仍需固定版本真实复验。没有前后可比样本时标为**规范改进候选**，不宣称因果改善。无需为验证规范另建基础设施或制造未授权付费作品。

## 七、历史证据的使用边界

历史只用于选择假设，不作为常驻修复清单。[H1～H5](../history/research/development-debugging-task-integration-2026-10-23.md#71-具名历史案例与本次设计约束)及[本次有效性审计](../project/tasks/CRE-01_creative-context-expression.md#e2e-effectiveness-audit-20261027)记录来源、反例和验证范围。V1/旧运行若只剩记录或夹具，就明确原始回执缺失；不能将后续版本PASS反填旧轮，也不能把跨版本局部成功拼成自主稳定。
