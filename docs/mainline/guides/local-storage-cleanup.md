# 本地存储手动清理操作单

适用于用户明确要求释放 Easel 本地空间的手动维护。关联 [STORAGE-01](../project/tasks/STORAGE-01_local-retention.md)。本页记录操作边界和真实结果，不代表新增自动回收功能，不替代现有运行状态检查。

## 下次执行入口

可以直接将以下指令交给仓库 Agent：

> 按 docs/mainline/guides/local-storage-cleanup.md 执行本次本地清理：先预览候选并核对运行状态，再在上述范围内删除历史调试 JSON、无用备份、已结束或已取消渲染的中间文件及确认重复的导出包。不创建备份，不动现用工作树、运行任务、正式数据库、成片、唯一配音和正式素材。UNKNOWN 按具体引用保护文件，不保护整个目录。记录删除数量、文件分配空间和磁盘可用空间前后差值，完成后报告实际结果。遇到无法证明安全的文件跳过并说明，不扩大成作品删除或功能开发。

本页同时保留人工操作单与[本机辅助脚本](#6-本机快速清理脚本)。脚本只覆盖保守子集；取消任务碎片、字幕底片、独有历史回执和无法确认用途的备份仍按本页逐项核对，不能把人工授权范围等同于脚本已实现能力。下面的只读盘点命令不执行清理。

## 1. 执行前核对

- 确认当前仓库根、Git HEAD、Dirty 和活动任务；不重置、切分支、停服务、部署或发生成调用。
- 用正式只读接口及生产库只读查询核对 Task/Run/Operation，结合 `lsof` 和既有渲染锁判断实际运行；单独一个 `needs_decision` 或历史 `unknown` 不代表正在执行。
- 检查符号链接、注册的 artifact / work_input 引用以及待处理请求中的具体文件引用。不能跟随链接清理仓库外文件。
- 记录目标文件的大小、分配块、inode、mtime；删除前再次核对，文件变化或被占用就跳过。
- 渲染文件删除复用现有 registration/execution/terminal 锁，并与存储维护锁互斥；短事务内重查任务状态，不改写生产业务记录。
- 不新建整库备份、媒体副本或大型状态快照；只保留小型清理结果清单。现用任务正在生成的记录不在清理范围。

只读盘点示例（在仓库根执行；不要据此直接递归删除）：

```sh
git worktree list
git status --short
du -sk .
du -sk outputs/_debug
du -sk outputs/_diagnostics
du -sk outputs/_production/renders
du -sk outputs/works
du -sk outputs/_production/materials
```

目录分别盘点，避免一次 `du` 多参数的硬链接去重导致分项口径不同；GB 统一按十进制展示。

## 2. 允许清理的文件

| 类别 | 清理条件 | 必须保留 |
|---|---|---|
| 历史调试 JSON | `_debug` / `_diagnostics` 中的历史状态、请求和回执副本；没有正式引用或在用证据 | 最近一小时有写入的整组记录默认跳过；活动任务的旧记录即使超过一小时也保留 |
| 数据库与发布前备份 | 用户明确授权删除的备份副本，身份和路径确认，主文件及侧车均未被使用 | 正式 `production.sqlite3`、`checkpoints.sqlite3`、素材 `catalog.db`、语义索引及其在用侧车 |
| 已完成渲染中间文件 | 已有可核实成片，Task 不在运行/等待外部结果；清理 montage、scenes、captions 等中间媒体 | 最终视频、正式产物、唯一配音和在用输入 |
| 已取消渲染中间文件 | Task 已取消/被替代且无执行进程、无活动锁、无恢复请求引用 | 不把缺少 output.json 视为整目录永久保留理由，也不因此删除疑似唯一最终视频 |
| 渲染暂存素材 | 渲染目录内的副本，正式目录存在 SHA256 一致的原件 | 找不到可核实原件时保留，尤其音频；不清正式素材库 |
| 重复导出包 | 渲染目录 `export.zip` 与同作品正式注册导出包 SHA256 一致，正式副本实际存在 | 唯一导出包、正式目录内导出包及最终 MP4 |

本次手动授权允许删除非成片的字幕底片。删除后，历史字幕预览或重做字幕不能再假设原底片仍存在，可能需要重新渲染；不伪造底片引用或检查成功。

UNKNOWN 不自动保护整个 Work：先核对其请求具体引用及共享文件。明确不被引用的已取消碎片、可验证重复副本可清；请求/回执、状态和必要依赖保留，不重新提交 UNKNOWN 操作，也不将其强制改为成功。

## 3. 删除与验证顺序

1. 建立候选清单，注明路径、类别、保留副本和跳过原因，不复制完整请求正文。
2. 核实最终视频及保留副本摘要，取得锁并重查状态；只删除清单内通过核对的文件。
3. 逐个保留最终 MP4、唯一配音及正式副本；目录中仍有未知内容时不使用整目录强制删除。
4. 清理后复核受影响的保留文件摘要、正式数据库存在性、原有任务状态和可用文件路径。若结果影响已知在用业务，立即停止剩余清理并报告，不启动重制补救。
5. 分别报告删除文件数、逻辑字节、可释放分配块、磁盘可用空间差值与剩余目录大小。并发任务和 APFS 会使差值不同；不能把逻辑字节直接称作精确磁盘释放量。

不为追求目录归零删除无法核实的文件。正式作品/历史成片/素材淘汰必须另走原有业务入口，不由本操作单隐式授权。

## 4. 2026-10-27 本轮实测记录

下表仅包括主项目清理，不包含此前 S5 工作树及备份删除。磁盘可用空间差值是各轮现场测量，期间可能存在其他进程写入。

| 轮次 | 实际删除 | 可用空间增加 |
|---|---|---:|
| 历史调试与备份 | 1057 个历史 JSON；9 个诊断数据库/侧车、197 个备份文件、4 个素材索引备份/侧车 | 约 7.456 GB |
| 首轮重复导出 | 12 个摘要一致的渲染导出包；36 个保留媒体摘要复核 | 约 0.507 GB |
| 已有成片的中间媒体 | 30 组渲染中的 1019 张字幕图、30 个底片、136 个暂存副本、145 个镜头；121 个保留文件复核 | 约 2.959 GB |
| 取消任务及 UNKNOWN 逐文件核对 | 26 组目录中的 86 个暂存副本、500 张字幕图、12 个重复导出包、4 个底片、59 个镜头；92 个保留文件复核 | 约 1.612 GB |

上述四轮合计现场可用空间增加约 **12.53 GB**。最后一次渲染目录占用为 **1,884,639,232 字节（约 1.88 GB）**，不是新的空间上限。

最后保留：2 组未结束或缺少可靠身份关联的目录；33 个暂存文件未能确认正式原件；9 个导出包未找到完全一致的正式副本。它们只是待核实项，不预先认定无用。成片和正式配音/素材未删除，未重启服务、恢复制作或新建备份。

## 5. 与自动回收的边界

已有代码入口为 `easel/production/storage_retention.py`。现行自动回收的保护条件与本次用户授权的手动范围不同；尤其手动清除了字幕底片和部分取消任务碎片，不能声称自动任务已经覆盖。

上述四轮只增加操作文档，不改变自动回收周期、备份保留策略、生产恢复行为或已部署源码。后续本机辅助脚本见下节；它不触发产品完整维护入口，也不重放前述一次性删除命令。扩展脚本范围仍须核对引用、用途和对应正反例，不固化历史临时目录或按目录名称直接清空。

## 6. 本机快速清理脚本

2026-10-27 按用户要求增加本机手动工具，便于重复预览和执行。它安装在当前 Mac 用户目录，不是仓库中的产品模块，不会随 Git 克隆自动安装；不新增定时任务、不重启服务、不部署或调用模型。目录根按当前用户 Home 推导，项目入口为 `~/Projects/Easel`。

- 启动入口：`~/.local/bin/easel-safe-cleanup`。
- 本机源码：`~/.local/share/mac-safe-cleanup/cleanup.py`；原有备份预览适配：同目录 `backup_preview.py`。
- 清单与结果：`~/.local/state/mac-safe-cleanup/<本次时间>/`；目录仅当前用户可访问。

### 6.1 快速操作

```sh
# 默认只预览，不删除任何候选文件
~/.local/bin/easel-safe-cleanup

# 重新生成并校验候选，然后执行安全范围内的清理
~/.local/bin/easel-safe-cleanup --apply

# 加入旧调试 JSON 的完整内容去重检查，仍只预览
~/.local/bin/easel-safe-cleanup --deep

# 执行常规清理及上述深查范围
~/.local/bin/easel-safe-cleanup --deep --apply
```

预览会在私有状态目录写入小型清单，不删除候选。执行不读取或信任上次保存的计划，而是重新计算；无需先生成一份整库或媒体备份。刚清理过后显示零候选属于正常结果，不以目录归零为目标。

### 6.2 每次检查什么

| 对象 | 脚本是否处理 | 实际判断与限制 |
|---|---|---|
| Chrome / GoogleUpdater 安装包下载缓存 | 常规范围 | 解析压缩包内版本并与已安装版本一致；更新器未运行，路径、占用及正式库引用检查通过；未知格式保留 |
| OpenClaw Node / Jiti 编译缓存 | 常规范围 | 仅固定编译缓存根中符合生成文件命名规则的普通文件；无占用、无正式引用、不跟随符号链接；其他文件不清 |
| 历史生产数据库副本 | 常规范围，额外保守 | 复用 `redundant_backups(..., dry_run=True)`；至少静置24小时；至少两份校验通过备份可保留；候选所有原始请求/回执须与正式库完全一致；身份/独有数据/恢复日志/占用不明时保留 |
| 完全重复的旧调试 JSON | 仅 `--deep` | 至少7天、SHA256一致且保留一份完整原件；文档/源码引用、正式库引用、占用或在途工作依赖均跳过；不删除剩余唯一快照 |
| 已完成/取消的渲染、重复导出、字幕底片 | 不由本脚本处理 | 产品现有日清与人工操作单分别执行；不把历史手动核验结果固化成通用删除条件 |
| 正式作品、素材、配音、数据库、配置 | 不处理 | 包括 `outputs/works`、正式素材与索引、Profile/频道/导演/音色、密钥、生产数据库及在用侧车 |
| 本地模型、Codex运行时、uv完整环境、浏览器依赖 | 不自动处理 | 使用状态会变化；模型切换、版本淘汰后重新核对实际配置、进程及跨项目引用，不能凭缓存名称删除 |
| 其他项目旧备份、下载文件、Git工作树、代理日志 | 不处理 | 不重复此前的一次性授权；代理日志未配置自动维护，仍保持用户取消后的状态 |

脚本的深查比第2节人工操作单更保守：含在途或 UNKNOWN 所属 Work 的快照暂时整体跳过，不代表产品规则改为永久保护整个 Work。独有回执和用途不明的恢复资料仍需人工判断；如确需删除，只保留必要的小型审计信息，不复制整目录。

### 6.3 验证与结果口径

有候选且实际执行时，前后核对 `.env`、正式素材目录数据库、语义索引及当前配置的 BGE-M3 文件摘要；读回服务状态、音色、频道和导演接口。保护文件或服务读回发生变化时提示人工检查，并保留结果，不自动回滚业务数据或重启服务。并行创作可能合法写入文件，不能把所有变化直接归因于清理。

删除受固定路径策略、`lsof`、符号链接/硬链接检查、inode/大小/mtime复核约束。备份执行前重新获取现有机制的候选；实际删除与产品存储维护锁互斥。共享硬链接直接跳过，不当作可回收空间。

每次生成 `plan.json`、`report.json`，有删除时逐文件写 `deleted.jsonl`，包括路径、类别、SHA256、逻辑字节和分配块。结果区分候选逻辑量、分配块与磁盘前后可用空间；APFS共享块、后台写入及审计文件开销可能导致差值不同。不把清单中的逻辑大小称作精确释放量，不记录密钥或原始请求正文。

### 6.4 建议使用频率与已测边界

- 平时由已部署的 Easel 每日维护负责其现有范围，本工具不主动调用含下载素材回收的 `storage_maintenance`，避免扩大到正式素材策略。
- 系统更新或积累一批开发缓存后，手动运行常规预览；有明显磁盘增长时运行 `--deep`。这只是使用建议，未创建任何定时任务。
- 模型、历史归档、独有调用回执或大数据库需要单独核对，不加入“全部清空”开关；检查失败就保留，不停止在途任务或发起重制。
- 本机验证：19项隔离测试通过，覆盖默认预览不删除、执行审计清单、路径越界/符号链接/硬链接、文件变化、占用、正式素材保护、正式库相对路径引用、Chrome版本不匹配/更新器运行，以及独有原始请求/回执保护。测试只使用临时根和临时库，无真实生成或付费请求。
- 真实常规/深查预览已运行，当前零候选；真实删除正例尚未用正式数据复测，不把隔离测试冒充生产删除验收。复测命令：`python3 ~/.local/share/mac-safe-cleanup/test_cleanup.py`。
