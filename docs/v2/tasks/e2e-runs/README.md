## 一、目标、职责与权限

S6 的目标是用户选定画像、频道、导演下的一部真实自主视频及人工审片。调试用于解决该路径的实证阻断；独立验收用于证明修复后无需工程介入也能走通。两者使用同一主流程、不同证据标签，不新建任务体系或产品 Gate。

- **Web 验收负责人**：默认由 ChatGPT 主导正式 Web 操作、首次失败记录、用户交互和独立审核；通过已获授权的浏览器工具执行，WebCodex 可用时沿用。用户指定 Codex 直接执行时也可由其承担，须记录实际操作者，不能把同一执行者自检称为独立审核。
- **工程负责人**：默认由 Codex 负责技术归因、最优修复、相关测试/构建、部署方案；具备当前合法权限和授权时，可直接完成宿主只读检查及本地部署，不固定禁止 `ps` 或服务管理命令，也不要求经另一代理逐条转发。
- **独立审核**：检查失败证据、Diff、关键断言、执行回执和已加载版本；按风险选取必要复核，不机械重复全量测试。没有独立审核者时明确标记待审核，不伪称完成。
- **Creator**：决定创作方案、费用、修订范围并亲自审片。代理不得冒充用户同意或接受。

### 1. 开始时填写实际授权

| 动作类别 | 必须明确的范围 |
| --- | --- |
| 只读诊断 | 代码、日志、进程、端口和业务库只读查询；敏感正文不得进入共享日志 |
| 工程修复 | 具名阻断、允许修改的模块/配置及关联测试、离线构建；保留既有 Dirty |
| 本地部署 | 获准重载的服务、允许的影响、恢复点、空闲及数据保护条件；不等于外部发布 |
| 真实生产/复验 | 对象、Provider/媒体范围、费用上限及真实调用/复验次数；含原作品恢复或新作品验收的具体授权 |
| Git | 目标分支和操作，按工程说明 §6 执行；受保护主线不可自动提交推送或合并 |

已有明确授权在其范围内持续有效，不因聊天换轮、执行者交接或普通测试失败反复索取。缺失字段不视为无限授权；超出费用/次数、扩大产品需求、改变冻结职责/合同、迁移/删除数据或操作其他作品前，需要用户决定。G3/G6 的产品确认不能被工程授权替代。

执行前核对当前工具能力、沙箱/审批策略及目标主机；旧 ACP 的限制不能推断为所有本地 Codex 的限制，完整访问也不是业务授权。明确拒绝不得换通道绕过；若是能力缺失或环境故障，记录实际错误与已执行副作用，确认合法执行途径后才接手。不默认调整 Provider、Model、Reasoning Effort 或 Thinking Level；实际模型无可靠证据记 UNKNOWN。

## 二、唯一主流程

**现场与授权核对 → 正式 Web 操作 → 首次失败取证/分类 → 最优修复与相关测试 → 授权部署 → 原场景安全定向复验 → 关键阻断解除后全新独立 E2E → Creator 审片。** 无阻断时直接完成 G0～G6；只有当前步骤获授权才执行，不因流程列出了后续步骤就自动获得权限。

### 1. 现场与记录

先读根 AGENTS、INDEX、CURRENT_STATE、本规范及当前具名任务；需求、架构、实施合同、ADR 和历史证据按问题需要读取。核对分支/HEAD、Dirty/未跟踪、受影响源码与构建指纹、实际加载版本、相关在途任务及 UNKNOWN。记录取证时间；不能把旧 PID、通过数或文档 PASS 当作实时证据。

以 `YYYY-MM-DD-web-e2e-NN.md` 记录一次真实验收及其关联调试；继续同一问题时追加修复/复验版本，不删除首次失败或重新编号掩盖它。全新独立验收另建记录并链接已解决问题。会话/作品/Operation 的真实 ID、个人画像、原始回执和凭证仅留本机受保护位置，不入 Git。默认画像从既有本机映射或正式 Web 当前选择读取，不把显示名称当数据库 ID。

已有 Dirty 正确就复用；实施前识别本轮增量和其他人的改动，发布前检查是否并发变化。不执行 reset/clean，不将整个 Dirty 当作本次可发布补丁；不能安全拆分发布对象时报告依赖与风险。

### 2. 正式 Web 路径 G0～G6

业务动作全部通过正式 Web 浏览器交互；日志、数据库和宿主检查仅用于取证，禁止用生产 API、改库、伪造回执或手工生成 MP4 代替用户路径。

| Gate | 可观察目标 |
| --- | --- |
| G0 | Web 已加载目标版本，用户选择的合法画像/频道/导演/音色依据就绪；独立验收建立全新 Conversation |
| G1 | 自然语言讨论通过受控入口创建/绑定本轮唯一 Work |
| G2 | 真实 Planning 产生语义完整且可核对的 Plan |
| G3 | 在原对话展示方案、范围及可能费用，取得用户对当前方案的明确确认 |
| G4 | 在合法 Rights/费用范围内完成真实素材、配音、剪辑、渲染及 QC |
| G5 | 可对应本轮 Plan/Run 的真实可播放 MP4 自动回传原 Conversation |
| G6 | 用户亲自审片，明确接受或提出局部修订 |

每 Gate 记录 PASS/FAIL/BLOCKED/NOT_TESTED。关键状态转换、确认、首次失败、收费操作和最终交付采用三重证据：Web 所见及操作、后端请求/状态/错误、对应业务对象和副作用。普通无状态变化的页面查看无需重复全库审计；证据不足标记局限，不将 HTTP/SSE 200 或助手自述当成业务成功。

G6 应覆盖旁白音色与自然度、画面与镜头意图、字幕准确完整可读、节奏/音画同步、实际片长及整体观感。没有实际人工反馈即未验收；不强迫用户逐项填表，但未覆盖项如实保留。用户未接受不能自动继续整片生产。

### 3. 首次失败与分流

保留期望/实际、首次失败回执、对象/版本、是否收费、在途/UNKNOWN、已做恢复与 Gate 影响。事实和假设分开；工程分类为 PRODUCT_BUG/TEST_BUG/ENVIRONMENT/UNKNOWN，准入按 SAFETY/CURRENT_BLOCKER/LATER/RESEARCH。

非阻塞问题可通过原 Conversation/Work 的正式恢复入口继续，前提是已核清终态、不会重复副作用且授权有效；记录 WORKAROUND_ONLY，不能当作正式修复。安全或当前真实阻断冻结相关业务动作，进入工程诊断；无关只读工作和隔离测试不必一并冻结。全部 ISSUE 可交工程负责人分类和归并，但只实施已授权的 SAFETY/CURRENT_BLOCKER；LATER 合并至当前状态的 S7 候选池，RESEARCH 保留原依据。

### 4. 最优修复

**以正确解决已确认阻断为目标，不设“一问题一轮”的工程修复次数上限，也不以最少改动行数为目标。** 比较根因覆盖、架构契合、可维护性、复杂度、恢复性、权限和成本，选择最优必要方案；有依据时可以结构性重构，不为保持小补丁而保留错误设计。

同一目标与授权内持续定位、实现、修正和复验，普通测试失败或新证据修正假设不要求重新授权。每次实质方案变化说明证据、影响和验收标准；不因出现新线索就扩成通用平台、S7 优化或无关历史治理。改变冻结职责/合同需先获用户决定。

根因未知时交付已确认/已排除事实、缺失证据和最小必要取证方案；不得硬编归因或为交付而修改代码。无新增证据的重复尝试、只能靠未授权外部调用推进、实际权限拒绝或不确定副作用无法排除时，停止受影响动作并说明具体决策点。问题已达到约定验收标准即收口，不为“还能更好”延长任务。

测试应覆盖原失败机制、受影响正反路径及拒绝/幂等保护；按改动选择相关 Python/Node、Build/Lint 与隔离集成，不机械全量重跑。不得通过改弱断言、Rights/QC、用户事实或授权边界换 PASS。本条是研发规则，不改变产品内自动修订次数、模型预算或重试策略。

### 5. 本地部署与核验

只有部署已获授权且适用软件检查完成时执行。具备合法权限的工程执行者直接完成以下工作，审核者按证据复核：

1. 确认目标服务、源码/构建来源及本轮增量，排除并发改写和会被中断的相关任务；只读检查 UNKNOWN 与本次重载的关联。
2. 保存必要代码/产物恢复点和数据保护依据，使用已有 LaunchAgent/脚本加载受影响组件；不默认重启全部服务、不自行迁移数据。
3. 核对新进程/启动时间、源及构建指纹、协议/工具和适用成功/拒绝路径，核查数据及受保护 UNKNOWN 未被改变。
4. 明确实际加载证明强度。若只有启动时间、发布源哈希与握手，按该组合报告，不能声称读取了进程内模块哈希；HTTP 200 单独不足以证明新代码加载。

回滚只恢复已核验的代码/产物及获准重载，不回滚业务库、授权、Operation 或用户媒体，不覆盖无关 Dirty。无法安全部署时保留已完成软件结果，不能宣称真实路径修好。

### 6. 定向复验与独立验收

**定向复验**优先保留原场景条件。代码已加载、对象状态兼容、无相关 UNKNOWN 重发风险、恢复入口真实存在且当前授权覆盖时，可在同一聊天窗口、原 Conversation/Work 经正式 Web 恢复并复验。记录代码/Plan/产物版本和工程介入，原失败不改写。没有兼容恢复入口时，不用脚本改库；必要的新作品对照须在授权内，并说明哪些条件变化。

**独立验收**在关键阻断解除、加载版本明确及真实生产授权有效后，建立全新产品 Conversation/Work，从 G0 完整到 G6。输入来自用户真实创作意图，不把旧 ISSUE 或调试指令灌入创作 Agent；工程侧仍可读取历史证据和安全状态，不要求失忆。若又需工程修复或手工绕行，保留该次失败/受助事实，转回调试；不能称为无需介入的自主通过。

独立性来自新业务对象、固定版本、真实输入和完整证据，不取决于是否新开聊天窗口。可在同一窗口完成调试和后续独立验收，也可因用户选择/上下文需要交接；无需每次强制重建作品。任何新的付费尝试都受既有费用及次数上限约束，不因工程修复可持续就无限生产。

## 三、中断与 UNKNOWN 的作用域

| 不确定对象 | 核验与禁止事项 |
| --- | --- |
| 工程 Session/Run/Job | 查原任务终态、命令回执及文件/进程副作用；未确定终止前不并发派发相同写入 |
| 部署动作 | 核实际进程、产物及加载情况；是否已执行不明时不重复重启或回滚 |
| Provider Operation | 查原请求既有回执/状态/账单；禁止自动重发，不改 UNKNOWN 为成功或失败来解锁 |

每项说明受影响对象、相关动作和可继续的独立工作。历史 UNKNOWN 原样保护；它存在本身不阻断无关诊断、测试或新作品。若关联共享服务重载、费用或数据风险无法排除，则阻断该动作。

工程任务已确认终止、实际副作用核清后，沿用有效补丁继续未完成步骤，不重跑整个任务；取消不等于没有改动，也不等于用户撤销所有授权。若用户明确取消/停止该工作则遵从，不通过新任务规避。无法核清时保留现场并报告；换窗口不消除不确定性。

| 现场 | 日期、分支/HEAD、Dirty、受测源码/产物指纹与实际加载依据、执行者及授权 |

| 真实验收 | SCENARIO_RETEST（定向复验）、REAL_PRODUCTION_PASS（真实生产）、是否全新独立且无需工程介入、CREATOR_ACCEPTED |

这些标签仅是文档证据口径，不新增产品状态。软件通过而未复验的 ISSUE 记“软件通过/待真实复验”；FIXED_VERIFIED 仅用于相关真实场景已验证修复的问题，不代表整条 E2E 或其他 ISSUE 通过。WORKAROUND_ONLY、BLOCKED、OPEN 保留真实含义；未运行记 NOT_TESTED，无证据不补 PASS。

当前状态页顶部只保留最新摘要与唯一下一动作；过程、命令和历史快照留原 Task/运行记录，历史“下一步”不再派发。达到真实生产及人工审片的阶段证据后，提交 S6 结果与 S7 候选供用户决定，不自动进入 S7、不自动发布作品。
