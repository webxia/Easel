## 2. 每张卡开始与完成的共同约定

**开始时**：确认分支/HEAD/status及用户本次授权；读本卡、设计相关节和必要源码。新阶段开始前Fetch/Diff/报告上游，不自行合入。保护现有未跟踪文件/outputs/Profile；使用独立测试根和fake服务。Python默认使用项目可用虚拟环境，不能把某台Mac的绝对路径写成跨平台命令。

**文件/接口**：设计中的API统一使用 `/api/production`。新测试统一 `tests/production/`，前端沿用 `node --test tests/frontend/*.test.mjs`（项目没有npm test）。新代码目录由实际卡创建，不提前造空模块。所有用户命令包含command_id；修改已有实体须带expected_revision，创建时为空；契约变化更新唯一设计和受影响卡。

**依赖与能力**：S6-04将LangGraph/checkpointer传递依赖按3.10/3.12和已有平台矩阵落实，不静默抬Python要求或打开云追踪。S6-09不能直接迁入V1机器特定parser。媒体/模型未配置时显示明确不可用，fake结果不能显示成真实生产合格。

**授权**：启动具体Coding任务后可改该卡业务代码、离线fake测试与许可本地媒体测试；真实模型或媒体服务调用、影响用户Runtime安装/生产重启、旧库迁移、合并或发布须按该任务具体授权执行。未取得真实服务授权不阻塞写adapter/fake合同测试，但对应真实验收保持未测。不要每个普通可逆代码编辑重复请求许可。

**完成定义**：真实实现+调用接通+必要正/反例+相关既有回归+清晰错误+文档更新；不能只有模型/表/空接口或mock演示就记完成。命令必须实际执行，pytest零收集/全部skip不算通过；缺服务的平台能力分列NOT_TESTED。CI成功必须绑定确切SHA，测试对前一SHA成功不能冒领新提交。

**回退**：开发代码可用独立分支/提交回退；新schema需要保留备份和向前修复策略，不对用户库随意downgrade。停用V2不能破坏原Web/聊天/内容库；已生成有效成果不清理作为回退手段。

**收尾**：按AGENTS允许提交并推送自己的开发分支，核查范围/敏感文件；建立或更新PR并附验证。更新当前状态只保留一个下一工作事项；不自动合并保护主线。运行结论区分软件、真实生产、自主完成、Creator接受。
