# Easel V2 · 路线图

状态：**CURRENT — 阶段与依赖**。只记录里程碑和转移条件；具体进度与下一事项见 [当前状态](04_CURRENT_STATE.md)，不要同时在两处维护逐日进度。

| 阶段 | 目标 | 可核查的阶段成果 |
|---|---|---|
| S0 · AI Coding 项目骨架 | 建立研发指令、愿景、需求、架构、工程与任务接续入口 | 文档互链与边界清晰；静态校验通过；新会话能读懂当前目标 |
| S1 · 当前代码能力审计 | 仅盘点 `easel-v2-rebuild` 既有实现，不引用尚未正式录入的新需求 | 形成代码入口、流程、已有能力、可观察边界和未验证事项的证据文档 |
| S2 · 新需求正式录入后再启动设计 | 待用户明确新需求及验收范围，现阶段不预设内容、字段或生产职责 | 将正式需求与 S1 当前实现分开对照，再确认下一步架构及实施路线 |
| S3 · 第一条真实视频 | Web 确认后走正式单线，得到可审阅 MP4 | 真实输入/模型/素材/制作/质量与恢复证据；不以演示脚本代替 |
| S4 · 质量、调用与恢复优化 | 基于已测量的瓶颈定点完善 | 成功率、Token、时间、干预与修订指标可比较且质量不倒退 |
| S5 · 产品范围验收 | 覆盖四音轨、1～900 秒、跨主题、真实故障与 Creator 审片 | 完整产品范围与失败反例证据，明确可发布版本资格 |

## 当前推进原则

- **先真实闭环、再针对实测缺陷优化**；必要的预算/幂等/结果保存机制应在首片前具备，不先打造通用分布式平台。
- 一个阶段可拆多个 Task，但不能为了凑流程增加独立 Gate。局部 PASS 不自动放行真实制作。
- S0 不授权任何真实模型、媒体生成、发布或生产数据迁移；后续按用户明确的具体执行范围推进。
- 长视频和四音轨是完整目标，不因首片是 45 秒就延期成“非产品范围”。
- 用户可以基于新事实变更路线图，变更时说明理由与对已接受需求的影响。

## 阶段结束时

相关 Task 的证据被验收后，更新 [当前状态](04_CURRENT_STATE.md) 中的结果和唯一下一动作；Roadmap 只在阶段设计或顺序实际改变时修改，不每天追加日志。
