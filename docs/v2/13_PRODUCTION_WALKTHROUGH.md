# S5 · 一条 90 秒视频的完整生产推演

状态：**案例及衔接方式已获用户认可；仍为纸面案例，非真实生产记录，未调用模型/生成/渲染服务**。2026-10-16。用户已认可主线和职责划分，要求先走完具体案例再确认架构，暂不急选框架。本文的素材、用户输入、授权、耗时、媒体时长和结果均为模拟条件，不是用户的真实经历、授权或已验证能力。主线规则见[架构 §6](02_ARCHITECTURE.md#6-主线衔接与大模型的分层创作)；本文用于发现交接缺口，不取代 S4 需求。

## 1. 案例输入

假设用户在科技频道发来：

> 做一条 90 秒竖屏视频，讲“工具越多，为什么我反而更难开始”。昨晚我打开五个工具窗口，却一直没开始写文章；后来关掉四个，只留下文档，才写下第一段。只讲这次经历，不要扩大成所有人的结论。沿用 AI 频道那位导演的风格。附件有桌面录屏和一段口述，口述里“工具是来帮我开始的，不是让我一直准备”的原声必须保留。其他画面可以找素材。

模拟已有设置：

| 项目 | 值与边界 |
|---|---|
| 主人设 | 直接使用已选六维画像 P；不新建、补写或推断新的经历 |
| 频道 | 科技频道 C，与 AI 频道属于同一画像；本片明确选 D-v2，不改变频道默认搭配 |
| 导演 D-v2 | 已通过参考拆解与试片接受：生活细节开场、克制讲述、近景与留白、字幕简洁、音乐不抢话；这是风格，不是必须套用的段落模板 |
| 声音与字幕 | 科技频道已有试听接受的模型音色 V，字幕白字细描边、下方安全区、1080×1920 下 48 px；字号为本例设置，不是产品全局标准 |
| 输入素材 | 20 秒桌面录屏 A；12 秒口述 B，其中模拟 4～8 秒为必用原声；原文件不可覆盖 |
| 规格 | 目标 90 秒，9:16，1080×1920 MP4；旁白+轻背景音乐，局部保留原声 |
| 素材策略 | 必用素材保留；允许范围内库内复用优先，新增素材外部优先，不足再申请已授权的 AI 补料 |

画像不等于导演，跨频道借导演不带入 AI 频道的题材、个人经历或音色。频道本身的音色和字幕继续有效，除非用户本片另指定。

## 2. 第一步：把输入变成可靠的创作依据

**输入**：上述文字、所选画像/频道/导演、附件和已有设置。

**程序先做**：登记作品 W、输入 A/B；探测可读性、画幅/时长/音轨，提取可供模型查看的预览、转写及时间定位；解析有效音色/字幕。此时不支付生成费用，不把自动转写当作必然正确的原话。

**模型决策**：结合实际原声确认必用句与区间，区分“本次真实经历”和“作者观点”。方向是把“忙着准备→真正动笔”的变化讲清楚；不编出“坚持三个月”“效率翻倍”或“心理学证明”。这是个人反思，不需要为了显得专业引入未经核实的研究结论。

**输出给下一步**：创作依据 B1，含用户给出的事实、核心观点、必用区间、参考材料、选定风格/设置和未决项。模型提出具体方向，不问已给过的时长、画幅或音色。

**失败衔接**：若原声区间定位不准，先重听/校准；若文件损坏无法恢复，才请用户补充必用原声。导演不能悄悄用 TTS 替代。其他可做的方案工作可继续，但不能宣称输入齐全。

## 3. 第二步：形成完整方案，供用户一次确认

**输入**：B1、附件实际预览、导演规则与工具能力信息；必要时先查看授权内外部候选，检验镜头可行性。无收费媒体生成。

**模型规划**：先决定表达重点，再形成具体脚本、镜头、声音和场景目的。以下是本例完整旁白草稿及目标分段，不是固定脚本模板：

| 场景 | 目标区间 | 旁白/原声 | 画面与声音设计 |
|---|---|---|---|
| S1 准备却未开始 | 0～18 秒 | “昨晚，我想写一篇文章。打开一个工具，又打开一个，最后屏幕上摆着五个窗口。它们都能帮上忙，可文章还没有开始。我一直在准备，却迟迟没有写下第一句话。” | 用户录屏 A 的可用片段，裁切强调多窗口；轻音乐，不加虚构聊天或成绩 |
| S2 困惑 | 18～35 秒 | “我看着这些窗口，忽然觉得，眼前要处理的东西比文章本身还多。先用哪个，接下来切到哪一个？工具已经打开了，注意力却还没有落到要写的内容上。” | 合法通用桌面素材，明确是辅助画面；不冒充用户昨晚的真实现场 |
| S3 转变 | 35～55 秒 | “后来，我关掉了其中四个，只留下文档。那些工具没有变差，我也不是决定以后再不用。只是这一刻，我想先把文章开个头。终于，第一段写了下来。” | A 中真实关窗片段；若 A 没有该动作，用简洁的示意图/编辑表现配合旁白，不能伪造原始记录 |
| S4 核心句 | 55～72 秒 | 先原声：“工具是来帮我开始的，不是让我一直准备。”再接旁白：“这句话只是我对昨晚那次经历的提醒。对当时的我来说，先动笔，比继续准备更有用。” | B 的必用原声区间完整使用，降低 BGM；保留停顿，回到安静画面 |
| S5 收束 | 72～90 秒 | “下次再遇到类似的时刻，我想先问自己：眼前这一步，究竟需要什么？需要的时候再打开其他工具。先让文档里出现一段文字，其他的事，再一步一步往下做。” | 留白与稳定近景，关键词字幕收束；结尾未来意向在方案中明示，由本次确认认可，不当作既有经历 |

这版草稿的语义重述、内心表达与未来意向均完整展示，不藏在“只是剪辑调整”里。用户可以一次修改/确认。时段是创作目标；实际音轨和节奏需要制作时测量，不能声称目前朗读恰好 90 秒。若实际长度无法通过自然停顿和已允许的非实质文字精简满足规格，需呈现差异，不能机械加速音色或擅自缩短成片。

**方案明确的边界**：事实、核心句、必用原声、风格、固定音色、目标规格不能擅改；辅助实景、景别、裁切、调色及不改变表达的剪辑实现可自主适配。脚本有实质语义变化需重新确认。画面应尽量真实，必要的抽象示意不冒充现实证据。

**模拟授权**：用户确认方案 P1；允许指定服务 AI 补料，生图最多 2 次、生视频最多 1 次；本次固定音色配音的收费条件已说明并获授权，配音不纳入上述两类次数。此条件仅用于推演，现实中尚无这些授权。

**输出给下一步**：绑定 P1 的确认与授权 U1；摘要和上述完整方案同源。确认无需用户分别批准五个场景。若用户改变核心内容，产生 P2 再确认，不能用 P1 的确认覆盖 P2。

## 4. 第三步：确认后转成可执行制作计划

**输入**：已确认 P1/U1、输入 A/B 和已有可用成果。

**模型决策**：逐场景列需要哪些媒体、哪些已足够、哪些要搜、什么可替代；明确每个镜头的叙事作用。比如 S3 的重点是“减少干扰后开始”，不是必须找一段原生带四扇窗消失动画的图库视频。

**程序衔接**：保存一个有效运行 R1。给场景稳定身份 S1～S5，登记素材/音轨/字幕/工程依赖；重复点击确认仍对应同一个有效执行。制作计划 M1 引用 P1，不复制另一套可自行改写的用户要求。

**输出给下一步**：按场景的素材任务，以及固定音色配音任务。互不依赖的工作可以并行：寻找辅助素材与准备旁白；最终剪辑必须等待实际素材和音轨时长。必用原声 B 不参与重配。

**失败衔接**：关掉网页不取消 R1。若服务重启，恢复先检查任务与外部操作，不让模型重新从头“接单”。若确认后发生明确取消，停止派发；在途操作的结果和次数保留。

## 5. 第四步：依据真实素材选材，处理不足与生成未知

**输入**：M1、真实库内/外部候选及其文件、来源、权益和检查结果。

**正常决策**：程序先做范围/技术/权益检查；模型看画面与有效区间，选符合叙事的内容，不只凭标签或文件名。假设 S1/S3 使用 A，S4 使用 B；S2 找到一段可合法使用的桌面近景。发现原片偏冷并非阻断，若适合内容且调色在范围内，可计划适配，不重新向用户确认。

**素材不足分支**：S5 所需留白背景没有找到合适且使用条件明确的候选。模型先判断能否用现有画面或普通编辑表现实现；假设本例这些替代会明显破坏已确认的收束效果，提出一张“抽象、无品牌、非真实经历证据”的背景图。程序检查 U1 和余量后提交一次生图，不因为有额度就顺便生成视频。

**生成结果未知分支**：假设服务已接受生图请求 G1，网络在接收回执前断开；本例服务支持按预先保存的请求键查询。

1. 程序标记 G1 待核实并保留一个名额，不当作“失败可免费重试”。
2. 查询同一请求，找到任务和结果；下载、核验、登记媒体 G1-A。
3. 核实后显示生图已用 1/2、生视频已用 0/1。查询与下载不加次数。
4. 模型查看真实结果再决定是否选用，不能因请求成功就认定画面合格。

若服务不能查询，也无法取得原任务身份，受影响任务保持待核实并说明问题；不假装总能恢复，也不自动重发。其他独立成果继续保留。若生成的图片不合适，新生成仍另算一次；额度不足才申请追加，不默认使用视频额度替代。

**输出给下一步**：已选媒体集合 A/B/外部片段/G1-A，每项附区间、用途、来源及权益/技术结果；M2 记录对 M1 的范围内适配。P1 保持不变，G1 身份不随计划修订消失。

## 6. 第五步：拿真实画面和音轨完成编辑创作

**输入**：P1、M2、已选媒体、固定音色 V、原声 B、字幕设置。

**模型决策**：实际旁白生成后，依据音轨停顿、语速和原声长度重排镜头长度。先安排情绪/信息节奏，再确定裁切、转场、字幕分句和音乐起伏。使用工具读取实际时长，不能靠估计填时间线。固定音色不能因服务报错换成另一种声音。

**程序衔接**：旁白按明确脚本范围与音色登记复用依赖，B 保留原声；测量音轨、对齐字幕、校验引用和时间线。配音暂时失败仅处理对应任务，不能重做所有素材。已有有效音轨不因新渲染而重配。

**模拟产物**：实际语音与原声加自然停顿约 87 秒，结尾画面/音乐自然延续约 3 秒，形成 90 秒工程 E1；这是用于说明调度关系的假设数值，未经合成测量。若实际差距过大，返回局部时序或脚本差异处理，不能靠长时间无意义留白凑数。

**输出给下一步**：E1 及依赖清单。程序确认其可执行后渲染候选 C0，记录真实文件和工程版本。不把模型生成的工程文本当作可播放视频。

**失败衔接**：缺媒体引用返回对应选材任务；工程格式错误返回具体错误修正 E1；本地渲染中断可重跑渲染，复用素材与音轨，不重新提交 G1。程序故障无法处理则保存现场报告，不靠改仓库救火冒充产品自主完成。

## 7. 第六步：基于实际成片自检并局部修复

**输入**：实际 C0、P1、D-v2 风格、技术检查结果和必要的画面/音频证据。

**程序检查**：文件能解码、目标规格、音轨和时长、引用与字幕时间等；检测发现的静音/黑场是线索，需结合有意留白判断，不能机械删掉创作停顿。

**模型检查**：真实听取/查看相应证据，判断是否仍讲原来的经历，风格是否一致，声音是否自然、原声是否清楚、字幕和画面是否配合。纯脚本审查或几张抽帧不能证明全片运动连续和听感；能力/覆盖不足必须记录，不能宣称全检查通过。

**模拟发现**：S4 的背景音乐掩盖了原声，S2 一条字幕越出画面安全区。这两个问题都不涉及改观点、换素材或新增生成。

**衔接方式**：缺陷绑定 C0 的位置→模型提出 S4 降 BGM、S2 调整字幕布局→程序形成 E2，复用全部媒体/音轨→渲染 C1→检查修复位置、相邻衔接与全片有效性。C0 的检查记录不会直接贴给 C1。

**输出给用户**：若必要检查通过，交付可播放首版 V1=C1，简述修复和生成次数。若仍存在遮挡/必用原声不清等问题，只能交待修预览。无进展或达到技术尝试上限则停止循环，保留成果并说明具体问题，不能为了“通过”改低标准。

## 8. 第七步：用户自然语言审片，最小必要修改

模拟用户意见：

> 结尾再安静一点，字幕大一点，前面都保留。

**输入**：具体首版 V1、意见、工程 E2、全部依赖及剩余额度。

**模型决策**：将“结尾”定位到 S5；结合“前面都保留”，建议只降低 S5 的音乐、减缓其画面运动、字幕由 48 调到 54 px。本例把字号改动也限定在 S5，并在修改说明中明确；若语境无法确定范围，才集中澄清这一处，不能默默改全片。保留旁白文字、音色、原声、前四段内容。

**程序衔接**：这是无新增生成、无扩大影响的局部修改，按用户指令执行，简述范围即可，不强制再审批一次。形成 E3/V2，验证 S5 字幕不溢出及 S4→S5 衔接。若渲染器必须重编码整个文件，可全片重渲染；这不等于重创作前四段，也不保证输出字节完全一致，需验证其内容未被改动。

**输出**：V1/V2 并存对比，生图仍 1/2、生视频仍 0/1；音轨和素材不重生成。此处自动修复出的内部 C0 与对用户展示的 V1/V2 使用不同称呼，避免把候选、首版和接受版本混淆。

**扩大影响分支**：若用户改为“把最后画面换成一段 AI 运镜视频”，先说明新增 1 次生视频、涉及 S5 和邻接处；用户对这个具体修改确认后，在原 U1 剩余额度和服务范围内执行，无需再次申请额度。若额度或服务授权不够，再集中申请差额/授权。此分支不与上面的实际计次结果混算。

## 9. 第八步：接受指定版本，保存并结束

模拟用户明确说“采用第二版，保存到科技频道”。

**程序动作**：接受记录绑定 V2 与其实际文件/制作版本，保存到内容库，保留 V1 和依赖；关联科技频道。不得自动发布、覆盖频道默认导演/音色/字幕，或把本片 S5 字号调整保存为长期偏好。导演 D-v2 本来已被接受，本片接受不形成新导演版本。

**后续**：基于 V1 创作新片也可以；新作品引用允许复用的媒体，必须重新建立自己的方案和授权，不能继承 U1 的剩余次数。删除聊天不等于删除作品或仍被引用素材。

## 10. 整条链到底传递什么

这是便于理解的语义标识，不是预定数据库表或协议字段。

```text
输入/来源 + 已有画像/频道/导演
  → 创作依据 B1
  → 完整方案 P1 + 用户确认/授权 U1
  → 制作计划 M1 → 真实选材后的 M2
  → 编辑工程 E1 → 候选 C0
  → 缺陷局部修复 E2 → 可审阅首版 V1
  → 用户局部修改 E3 → 可审阅新版 V2
  → 接受 V2 的记录与内容库引用

外部操作 G1 单独保留身份；更换 M/E/V 不能清零消耗或再次提交 G1。
```

每次模型任务都获得必要的 P1 约束、适配许可、当前相关场景、真实媒体/工具结果和已完成成果；不是每次携带整段历史聊天，也不是仅传一句摘要。程序核验身份、依赖、权限与状态；模型判断内容/风格/语义影响。模型想改核心观点时提出差异，不能直接替换 P1。

## 11. 案例暴露的重点及下一步

- 确认后的方案与实际制作计划需要区分，否则容易在“不能变任何镜头”和“整片随意重写”之间摇摆。
- 原声、旁白、字幕、背景音乐需有明确依赖；全片重渲染不应触发全片重生成。
- 没拿到真实媒体不能完成选材；没检查实际视听不能宣称合格首版。
- 外部生成未知必须独立于模型重试处理；无查询能力时应诚实停在待核实。
- 局部修复需描述语义范围与相邻衔接，不能仅按文件变化推断安全。
- 主线正常情况下只有方案确认和最终接受两个主要交互点；用户自发修改、实质变更和授权缺口各按实际需要交互，不新增逐阶段审批。
