# S5 · 主线衔接、模型职责与开源执行机制研究

状态：**研究依据与验证计划，不是实现或选型验收**。2026-10-16。用户进一步要求：考虑 V1 未跑通的教训、开源项目和设计理念、每一步的衔接与大模型如何规划创作。主线职责与行为唯一维护在[架构 §6～9](02_ARCHITECTURE.md)，本文保存研究理由、证据和选型验证方法。

## 1. 从 V1 问题反推应检验的设计

依据为[S3 固定复盘](https://github.com/webxia/Easel/blob/4a92247b071c31d37ed623327d8058e62c64037b/docs/v2/10_V1_LESSONS_AND_REQUIREMENT_INSIGHTS.md)、[S4 差距](11_REQUIREMENT_GAP_MAP.md)及架构 §2 已读取的 V1 代码。私有原始日志不公开。V1 存在有效素材能力、合法阻断与局部成功；这些不能证明完整自主闭环，失败也不能未经验证都归因于一种技术。

| 观察到的问题/风险 | 本次设计如何回应 | 仍需证实的部分 |
|---|---|---|
| 完整确认与适配许可未传到后续任务，导演创意变成素材硬约束 | 方案修订是权威；任务携带完整必要约束与适配许可；真实素材到来后允许范围内细化 | 新任务上下文是否保留关键许可、避免重复询问 |
| 重复/大量审核扩大问题，技术成功但无有效业务产物 | 阶段以真实产物推进，检查说明具体缺陷；格式与业务接收分开；不默认多模型层层审批 | 精简后是否仍检出事实、声音、权益和风格缺陷 |
| 已有结果未正确识别，重试与预算责任分散 | 产物引用与外部操作持久记录；先接收/复用；一次生成由单一准入点执行 | 网络与落盘之间的未知窗口不能靠框架名称解决 |
| 历史内容、研发指令和大协议增加上下文负担 | 当前任务证据由程序组装；模型不回抄身份与授权；实际验证指令/工具隔离 | 精简上下文后是否丢失全片连续性；Harness 是否真的隔离 |
| 局部修改牵动整体，人工修复后被误称自主 | 直接依赖与语义影响一起确定修复范围；同版本记录人工干预 | 编辑工程能否可靠保护未修改声音/文字和历史版本 |

## 2. 开源依据：借鉴机制，不直接复制产品流程

以下为官方资料及实际读取的源码片段；是有界研究，未安装框架、未执行其测试，也未审计整个仓库。固定 SHA 是本次抓取时的 HEAD，后续实施应固定依赖版本并复核兼容性。

| 来源 | 核实到的机制 | 对 Easel 的推论/限制 |
|---|---|---|
| [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) | 区分预定流程与模型自主决策；从简单可组合模式起步，以实际收益增加复杂度 | 阶段推进稳定，创作选择保留弹性。不能由此推出固定脚本模板或必须多 Agent |
| [LangGraph：Thinking in LangGraph](https://docs.langchain.com/oss/python/langgraph/thinking-in-langgraph) | 区分模型、数据、动作与人工输入任务；按错误类型恢复 | 对照素材不足、格式失败、暂时网络错误和授权缺口，避免统一“再试一次” |
| [LangGraph：Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)及[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) | 有持久检查点与恢复机制；中断恢复可能重新执行节点前半段 | 确认与付费发送不能随意包进同一可重放节点；检查点不替代用户授权或外部操作记录 |
| [DBOS：Python guide](https://docs.dbos.dev/python/programming-guide)及[Architecture](https://docs.dbos.dev/architecture) | 普通代码步骤持久化并重放已完成结果；未完成步骤仍需考虑重复执行。Python 入门默认 SQLite，通用架构介绍侧重 PostgreSQL | 适合比较“原生 Python 执行 + 持久步骤”；不能把演示配置或数据库事务解释成外部付费恰好一次 |
| [Temporal：Activities](https://docs.temporal.io/activities)及[Python SDK](https://github.com/temporalio/sdk-python) | 确定性工作流与外部动作分开；活动重试要求考虑幂等 | 对 Easel 有价值的是决策/副作用边界；当前单机范围不自动需要独立工作流服务，取消也不等于外部生成撤回 |

实际源码核验：

- [LangGraph `_retry.py`，4e2dfe4](https://github.com/langchain-ai/langgraph/blob/4e2dfe4a247abfc0d001f3ef8242cbbbba400d2c/libs/langgraph/langgraph/pregel/_retry.py)：读取同步重试循环，重新调用任务，按匹配异常和 `max_attempts` 决定是否重试。**推论**：Easel 应按业务动作定义可重试性，不能仅凭 HTTP 异常给整个制作节点重试。
- [DBOS `_core.py`，61426cb](https://github.com/dbos-inc/dbos-transact-py/blob/61426cb95bcd749dd18137b4eb483d02b9975d7d/dbos/_core.py)：读取 `record_step_result` 与 `check_existing_result`，先执行函数再记录结果，重放读取已有结果。**推论**：外部请求成功而结果尚未登记时仍有窗口，需应用操作身份及核实逻辑。
- [Temporal `common.py`，346d4dc](https://github.com/temporalio/sdk-python/blob/346d4dcd0863657c3a33283c952a296762059339/temporalio/common.py)：`RetryPolicy.maximum_attempts` 默认 0 表示该配置无最大次数。此处不等于所有工作流默认无限重试；**推论**：不能不区分动作就照搬重试默认值。

## 3. 选型判断

| 实现候选 | 优点 | 必须承担的成本 | 当前建议 |
|---|---|---|---|
| 小型显式 Python 流程 + 持久记录 | 可直接适配 Easel，抽象少，行为可逐项检查 | 自己实现恢复、等待确认、执行者所有权和调度；“代码少”不等于可靠 | 作为对照基线，不先承诺自研全部机制 |
| LangGraph 有界流程 | 语义分支、人工确认和局部循环表达较直接 | 检查点/领域记录边界、重放副作用、任务隔离和依赖版本仍需集成验证 | **优先验证候选**；阶段内可创作，不能采用任意动作的全能代理作为主线 |
| DBOS 嵌入式持久执行 | 与普通 Python 编程接近，步骤恢复机制可复用 | 本地运行与所选数据库、等待交互、代码演进及外部副作用窗口需验证 | 若 LangGraph 集成复杂度过大，作为替代候选 |
| Temporal | 明确的持久工作流/活动边界 | 引入运行服务、运维和确定性/版本演进约束；对当前本机产品成本较高 | 借鉴原则，本期不默认采用；未来部署需求变化再评估 |

这不是依据流行度作结论。优先级是对已确认产品流程的设计判断，尚无对照运行证据。一次只选一个主编排所有者；不同时堆 LangGraph、DBOS、Temporal。业务授权与产物版本接口不绑定框架状态格式，方便实测失败后替换候选。

编辑/渲染仍须另评估：Hypit 原生制作与局部修订对照现有 FFmpeg/原片工具。执行框架不提供导演风格、素材权益、自然旁白或剪辑质量，框架选型不能替代这些验收。

## 4. 冻结前的最小对照实验

先离线验证编排，再在明确授权下做真实媒体生产。以下均 **NOT_RUN**，不是本轮已通过检查。第一轮对照 LangGraph 与小型显式流程；两者若均无法合理满足，再扩展 DBOS。不安装全部框架来堆比较表。

| 实验 | 操作与必须观察的结果 |
|---|---|
| 完整正常主线 | 用相同无付费工具替身跑输入→确认→选材→工程→检查→审阅；事件、产物、版本一一可追溯，正常阶段无需用户重复确认 |
| 交接内容保真 | 带个人事实、观点、适配许可、必用素材、固定音色和字幕的样本；逐阶段检查上下文，不因裁剪漏项、不把创意变硬约束；此实验与真实模型语义验证分开 |
| 重复与过期确认 | 相同确认发送两次、老页面确认新方案；至多启动一个有效运行，旧确认不得误确认新版 |
| 外部提交崩溃窗口 | 模拟发送前、对端接受后回执前、结果登记前中断；同一操作查询/接收，未知不盲重发，次数不因恢复归零 |
| 等待与取消 | 关页、重开、程序重启、等待追加额度、明确取消、过期执行者返回；有效阶段可恢复，取消后无新派发，旧执行者不能覆盖当前产物 |
| 局部返工 | 缺一个场景素材、字幕改字号、旁白改一句；只让必要依赖失效，声音/文字保护与段间连续性可检查，旧版可比较 |
| 错误分流 | 网络错误、格式错误、无素材、无进展、程序异常分别返回对应处理；未验证的替身输出不得标记真实成片合格 |
| 存储/运行成本 | 比较需要的新增服务、依赖、恢复代码、持久写入点、排障步骤及与 Easel Web 的接入复杂度；记录实际数值，不凭架构图评分 |
| 运行版本演进 | 有等待任务时升级代码或改变流程；旧任务能明确续跑或受控暂停，不能静默跳阶段、重置授权或重复发送 |

所有安全反例必须满足；更低代码量不能抵消重复提交或版本错绑。若候选需要额外一套生产状态才能成立，应重新审视边界。软件实验通过后才比较真实模型的素材适配、风格连续、首版质量、局部修改与人工干预次数；真实样本覆盖和费用遵循 S4，不在这里新设付费授权。

**冻结条件**：用户认可主线/职责方向，技术选择有上述对应证据，残留风险和未覆盖范围明确记录。软件实验通过仍不等于真实生产或 Creator 接受。
