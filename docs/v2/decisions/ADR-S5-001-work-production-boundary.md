# ADR-S5-001 · 作品确认与生产执行边界

- **状态：PROPOSED，整体待评审；主线与职责方向已获用户认可，不能扩大解释为本 ADR 全部接受。**
- **关联需求**：V2-EXP-005～008、012～013、019～021、024～027、031～034。
- **背景与证据**：[S4 差距清单](../11_REQUIREMENT_GAP_MAP.md)和[架构评审稿 §2](../02_ARCHITECTURE.md)。Easel 已有画像/聊天/附件/媒体工具；V1 有素材库和作品执行代码，但旧阶段调用预算、执行协议和用户范围不能直接沿用。S3 区分了成功复用、合法阻断、自主失败和待证的多状态风险。

## 候选与推荐

| 选项 | 判断 |
|---|---|
| 仅增强 Chat/Skills | 保留作为入口与工具，不能以提示词独立保证作品版本、外部操作和次数边界 |
| 整体搬 V1 | 不选；旧依赖和范围不符，不能用历史局部成功认领可靠主链 |
| 现有底座 + 作品执行边界 + V1 素材能力 | 推荐；职责由已确认需求驱动，不要求多服务/多 Agent |
| 分布式工作流平台 | 本期不选；无本机单用户范围以外的需求依据 |

## 建议决定（尚未生效）

1. 现有六维画像就是主人设。新增频道及导演版本关系，不新建重复 Creator 档案。
2. 用户确认特定方案修订和授权；程序保存版本、身份、引用及次数，导演做叙事、选材和语义判断。
3. 新 V2 作品由一个有效生产执行者推进。Web/Chat/Skill 是入口或工具，不形成绕过授权的第二制作流程；既有非视频功能保留。
4. 迁入素材库、复用、权益、供应和生成记录能力；不整体迁入旧 Creation/Delivery/Hypit 执行协议、数据或凭证。
5. 用户额度仅计实际生图/生视频提交；预留与已提交区分，未知结果保留原操作身份并观察，不盲重发。
6. 新作品元数据/操作记录推荐本机 SQLite，媒体仍为文件、画像仍为既有六维文件；这是本 ADR 待评审的存储选择。具体表与迁移代码在批准后细化；SQLite 不等于持久执行方案。
7. 主线按创作方案、真实素材制作、局部修订三层规划衔接，阶段以真实产物而非模型完成声明推进；阶段内保留导演自由度。
8. 此前研究建议 LangGraph 为有界编排的优先验证候选，小型显式 Python 流程作对照，DBOS 为备选；不叠加多个编排器。依据和冻结前实验见[主线研究](../12_PRODUCTION_FLOW_RESEARCH.md)。此优先级尚未经过运行验证，且用户最新要求暂缓选型，先评审[完整创作案例](../13_PRODUCTION_WALKTHROUGH.md)。

## 代价、边界与验证

- 需要新增作品命令、版本和持久执行记录；不是零成本复用。
- 网络与本地事务无法实现跨系统原子提交。使用原操作身份、可核实回执、UNKNOWN 和用户可见的待核实占用处理窗口，不承诺外部 exactly-once。
- Agent 不能拥有绕过付费准入的凭证/通道；Harness 的实际隔离能力须验证。不能仅依赖系统提示。
- 素材存储与作品记录跨写入需幂等接收和对账；旧素材库内部存在数据库不等于它拥有用户额度或生产状态权威。
- 本稿不选定模型、Provider、Hypit 版本或最终渲染引擎；渲染候选与验证见架构评审稿 §9。
- 软件反例：重复确认、过期版本、并发提交、发送前/后崩溃、取消、未知任务、过期执行者、局部修订保护、删除引用。
- 真实验收：同版本 Web 到首版/审阅、跨题材风格、1～900 秒及四声音模式；单纯软件通过不替代。

## 接受依据与重新评估

部分方向已认可：用户明确认可主线与职责划分，同时要求先走完具体案例，再确认架构，不急选框架。该认可不包含存储、执行框架、渲染器或所有具体接口；本 ADR 保持 PROPOSED，整体接受后才改为 ACCEPTED，并记录实际批准范围；不提前进入 S6。

若现有 Harness 无法隔离付费通道、SQLite 故障测试无法满足所有权/恢复、渲染候选无法兑现范围，或出现多主机正式需求，应重新评估相应选择，不能静默改产品目标。
