# 创作临时网关环境释放修复

授权来源：2026-10-03 用户要求删除本次失败创作的全部数据，并解决运行环境未释放的根因。

## 范围与原因

- OpenClaw 2026.9.4 的 MCP 环境按会话保留，空闲回收默认值为 0；本机 `mcp.sessionIdleTtlMs` 未设置。
- Easel 的素材视觉核验按输入身份建立独立会话，持久记录执行终态后未释放其 MCP 环境，最终触及网关 256 个活跃环境的限制。
- 修复现有 Delivery Agent 边界的终态释放和中断接续；不改变素材适用标准、Material V1.3 或费用/执行准入，不实施尚待审阅的三步耗时方案。

## 实施与验收

1. 提交前保存作品专属会话 key/agent 身份；只有带结束时间、非 yield 的 `ok/error` 终态允许释放。
2. 依据当前安装版源码，调用 `sessions.abort(key, agentId, clearQueued=true)`，该接口等待 `session-stop` MCP retirement，保留会话历史。runId-only abort 不负责此释放；不以删除 JSON 索引或一次断连当作释放。
3. 先保存待清理状态，确认 `ok/no-active-run` 后保存已释放；响应丢失或返回不完整时通过原 `observe_agent` 接续清理，阻止新模型派发。停止、修改方案或交付后仍核对原有未知执行并接续终态清理；不会将停止新工作当作网关任务已经结束。
4. 仅保存白名单错误分类，环境上限错误不再被通用执行失败掩盖，不保存原始网关响应或凭证。
5. 本机隔离 easel profile 开启 300000 ms 空闲回收兜底，网关热加载，不修改其他 profile。该值是本机运维配置，不代表所有安装均已配置。
6. 先核实失败作品无活跃网关执行/Build，通过正式 sessions.delete 删除其专属会话，再删除 Creation、Attempt workspace、聊天绑定、专属快照和残留归档/日志记录；保留其他作品与共享素材。

确定性验证扩展原网关提交/对账及隔离 Authoring 场景：未知执行不释放、终态释放、清理响应丢失/无效响应、重启接续、不同 profile 拒绝、成功缓存不重新执行、失败原因脱敏，以及隔离产物仍可提升。真实模型/成片效果不属于本次修复验收。

当前验证与本机删除结果只汇总到 `docs/02_CURRENT_STATE.md`。
