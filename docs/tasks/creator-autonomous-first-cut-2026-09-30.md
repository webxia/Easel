# Creator 自动交付可看首版

状态：方案已建立，待按下述顺序实施；当前没有代码变更或新的真实制作验收。本任务承接用户明确要求：前期方案确定后自动运行，同时系统性降低制作失败。不是将既有音画 E2E 改判为通过。

## 产品合同

Creator 负责创作意图、方案和最终取舍；Easel 负责中间制作。正常路径：讨论并确认方案 → 后台自动制作与质量检查 → 呈现可看首版 → 接受或提出修改。关闭页面、刷新、切换会话不影响已授权任务执行。首版后最终批准继续绑定当前输出 SHA、入库且不发布。

方案确认冻结内容、规格、Director/Creative Mode、硬约束、允许自动调整范围，以及费用授权范围。系统可在已确认边界内选择素材、裁切、排字幕、混音和做非付费修复；不能自动放宽无人物/Logo 等硬条件、改变事实表达、冒充用户经历或扩大付费授权。不是每个作品都需要详细人工填写这些字段，已有明确内容和系统可解释默认项由系统形成方案，只询问改变方向的真实歧义。

仅以下情形打断 Creator：影响方向的重要缺失信息；无法核实且不能安全删改/替换的事实或权利；授权外或不可核价费用；最终成片取舍。系统失败不默认变成审核任务；必须先执行有证据、受限且可恢复的解决路径。同一输入/素材/适用范围的已有声明不重复确认，发生实质变化则重新判断。

## 已核实根因

| 根因 | 代码或运行证据 | 修复方向 |
|---|---|---|
| 自动化依赖页面存活 | FilmOperatorPage 的 useEffect 运行 Runtime/validate/estimate 及不确定提交对账；服务 Authoring 活任务表为进程内 `_AUTHORING_TASKS` | 后端成为唯一推进者；页面只读取和提交人的必要决定。 |
| 技术自由度过高 | 隔离 Authoring 由模型写 SVML/SVS/Run 及多份制作文档；有补齐/合同修复，但真实运行仍出现引用、截取时钟、恢复副本身份问题 | 常见制作走受限结构化编辑决定，Production adapter 确定性输出安装版合同；不让模型生成身份与重复的技术字段。 |
| 计划与执行能力脱节 | 真实 BGM 来源条件与供应渠道冲突，复杂镜头描述变成检索词 | 计划前检查可用能力，供应候选按声明条件筛选；缺口先自动补充而非转交 Creator。 |
| 语义证据与首版质量能力不足 | 无已配置的可靠视觉分析器；五个视觉 Need 要人核对；首个技术 pass 输出 Scene 4 近黑、字幕对比不足 | 建立资产区间观察与首版质量证据；确定性问题自动修复，未知不伪装 pass。 |
| 恢复与授权粒度不匹配 | 可信 checkpoint 已可复用，但失败需用户阶段重试，零第三方计费仍需费用按钮；成本批准代码要求正预算且明确不是硬上限 | 持久调度与分类恢复；区分零媒体费用、已有授权和新增付费，不复制旧批准或虚构预算保障。 |

外部模型 502/400、认证及 Provider 不可用也会失败；不宣称确定性代码能消除外部故障。目标是少发生、早发现、在安全范围内自行恢复、避免重复付费，并给出真实停止原因。

## 校验是否造成失败：先审计，不继续机械加门禁

当前证据支持“设计/集成不稳定与校验责任分配不当是主因”，不支持“删除校验即可稳定”。trim 超界是真错误且检查过晚；局部修改声音是真范围漂移；native validation 副本遗漏身份记录则是校验链自身 Bug，不是用户输入不合格。素材逐项人审与零费用确认属于人工负担，技术检查数量不能与人工确认次数混为一谈。尚未测量校验耗时占比，不能声称多校验是耗时主因。

第 1 阶段开始时先建立现有校验清单：风险、权威输入、生产者/消费者、触发位置、是否模型调用、是否要求人工、缓存失效条件、耗时和失败类别。实际阻断需区分产物真错误、适配/副本错误、外部故障、信息/能力缺口及创作不满意，不能统一进入模型重做。

| 类别 | 处理 |
|---|---|
| Rights/Match/Readiness、输出身份、费用 fingerprint、幂等/对账等独立风险 | 保留正式语义，系统执行；真实缺口才停，不转化成重复人工表单。 |
| 同一可信输入上的重复昂贵检查/模型判断 | 在输入身份和检查版本绑定下复用证据；相关输入改变才重算，修改期间证据/字节变化不能命中过期缓存。 |
| 表示形式、冗余字段、可确定的格式差异 | 先在适配器按明确合同规范化，再核验；不让模型反复修语法，不接受身份/未知字段或实际内容漂移。 |
| 派生文件、隔离副本、合同版本等集成错误 | 修复生成/复制/安装版适配的根因；不能要求 Creator 重新声明，也不能以跳过检查解决。 |
| 纯过程确认与同一事项重复确认 | 移除或归入方案授权，保留实际批准来源；零费用自动执行需显式调整原授权实现。 |
| 只有格式正确、没有独立风险保护的检查 | 合并或移除，经现有高价值回归证明没有降低边界保护。 |

“提升前/提交前”检查处于不同可信边界，不能仅因检查名相同删除；可复用不可变输入的昂贵结果，但提交前当前身份、费用、源字节/证据有效性仍须确认。修复优先让生产者不再生成错误，不靠无限重试、更多提示词或无限新增 validator。新的质量检查先复用现有证据并验证检测效果，不为不可靠判断增加新的强制人审。

## 实施顺序与边界

### 1. 后端自动推进及持久恢复（先做）

- 在现有 Creation/Attempt 生命周期上增加最小持久执行记录：当前动作、输入身份、操作 ID、checkpoint、活动租约、次数、最后可信结果和恢复类别。复用既有阶段函数，不建立第二条状态机或视频生产链，不先引入通用工作流平台。
- 服务端从已确认方案推进 Preparation/Planning/Material/Authoring/Runtime/Plan/Pricing/Build/Export/技术 QC，自动动作只在相应既有门禁成立时执行。按依赖串行，独立只读检查才并行。
- 状态写入与派发必须有幂等声明；到期活动不能仅凭“运行中”状态判定可重发。启动时核对实际活动/正式结果；未完成的安全本地步骤恢复，提交不确定先对账，不重复请求 Provider/Build。
- 前端移除推进副作用，保留读取、停止和必要的人类决定。不会因打开多个标签或换会话重复派发；停止禁止新动作，已提交外部调用按真实取消能力/对账规则处理。

验收：确认后关闭页面也能走到应有结果/真实阻断；重启、双 worker、重复事件、完成落盘与状态更新之间崩溃均不重复供应或制作。必须核实部署是否多进程并选择可跨进程的锁/租约机制，不能只用内存锁。

### 2. 自动执行授权与费用策略

- 正常非付费制作由确认方案覆盖。正式价格证据明确无第三方媒体计费的本地 Build 自动推进，保留检查、fingerprint、核价及自动授权来源记录，不能在 UI 中偷偷模拟人工批准。
- 付费请求在初期仍使用现有明确批准；完整目标是方案阶段一次声明本作品允许的调用类型、次数/费用额度和重做边界，服务端在每次调用前核价、预留、按幂等请求结算与核对。不能把一般“开始制作”当付费授权。
- 这是既有逐请求人工批准策略的明确变更项，需实现相应授权契约及回归后启用；旧授权不得自动扩大到新调用。费用记录继续绑定当前 Plan/Pricing/fingerprint，不能复用过期批准。
- 实际消费上限不能核实、单请求不能估计上界或未知账单未对账时，不宣称硬预算；相关新付费动作停止并集中询问。已知零媒体费用仍可能有模型/算力成本，文案必须区分。

验收：零媒体计费正常路径无费用按钮；授权内的受支持调用不重复询问，预算预留并发安全；超额/未知/过期授权阻断，不增加请求。不得用真实付费调用测试。

### 3. 稳定常见编排，减少失败面

- 首期覆盖已验证需求：30～45 秒、4～6 场景、9:16、素材镜头、普通话旁白、分句字幕、BGM；这是一组制作能力，不把内容固定成模板。保留 Creator/Director 的内容、构图和节奏决策。
- 模型负责结构化创作/编辑决定：选用合格资产、具体区间、主体构图、镜头时序、字幕与声音意图。Production authoring adapter 确定性生成与当前安装版一致的 SVML/SVS/Run 身份记录、整数帧换算及组件引用；先核对 Hypit 版本和真实源码。不引入 Material Domain 内的 Hypit schema。
- 使用当前已冻结的 Script/Plan/准入素材建立单一可信输入；确定字段不在不同模型轮次重写。普通构图修改只修改受支持字段，保护声音/字幕/未涉及场景，不整片重生成。
- 继续使用现有 Authoring 边界、隔离/准入/静态 check 与 Hypit 主链。超出受支持能力时在方案阶段明确说明，不静默切换成另一条不受控制作路径。

验收：确定性方案经过真实本机静态 check；保护时钟/trim/引用/Run 身份/音画依赖，常见编排不需要模型猜语法；相同素材无需重新获取。源码合同变化应启动前报告兼容问题。

### 4. 可执行规划与自动素材证据

- 计划前检查来源、已配置能力和制作规格；只生成当前可供给/可制作的普通方案。只有用户的硬条件才冻结成硬来源约束，系统选择不能伪装用户要求。
- 候选搜索、筛选与补料优先自动完成，仍使用现有 Supply/Match/Rights/Readiness。同素材用于不同 Need 的证据独立；区间、裁切及构图都进入 Production 选择证据。
- 自动视觉观察是必要能力依赖：先对现有/可用分析器做契约与误判评估，检查关键区间主体、人物/手/Logo/文字、裁切适配。技术时长与来源元数据不能充当语义匹配，Creator 也不应成为默认逐素材审核员。
- 确定性音频检查核对声轨完整、时长/静音/削波；语音文字与脚本一致性需要可靠识别证据，不能只看生成输入便当作实际发音正确。已有本片人审证据不得伪装系统自动识别。
- 失败候选按有界搜索/重选策略替换；无法可靠判断硬条件时先尝试更可信候选或允许的替代，不放宽条件。没有分析器时自动素材验收只能记未就绪，不能承诺无人介入。

验收：语义不匹配、未知权利、Logo/主体条件缺乏证据仍阻断；足够证据的普通素材自动准入。有界补料只请求缺口，身份与已通过证据保留。

### 5. 首版质量检查与有界修复

- 制作前检查片段主体可见、时长、竖屏裁切、字幕安全区/背景对比策略、旁白占用和基础混音；制作后检查黑场/冻结/解码、实际字幕显示、音轨缺失/异常、场景与声音时间线，结合观察证据检查语义及风格。
- 可确定且在方案范围内的问题，自动换同资产区间、调整支持的构图/字幕样式/音量，并重新检查。纯技术修正与创作决定区分；变化涉及硬约束、事实、内容或费用时按原授权边界处理。
- 自动修复须有次数/时间/费用上限和改善证据；同错误不盲目重做。初期具体阈值由基线测量后确定，不能把未评估的检测阈值当可靠质量标准。
- 首版通过后主动呈现在作品画布，用户只判断接受/修改；一般反馈和时间点反馈保留真实可执行范围与费用说明。

验收：确定性回归覆盖本次暗开头/低对比字幕/trim 越界/声音被修改等真实风险；人审仍是最终取舍，自动 QC 不冒充 Creator。

### 6. 统一恢复与性能观测

- 输入合同错误：确定性纠正或限定范围修复，不重跑全部模型。短暂模型/网络错误：有上限退避重试；认证/配置/不支持的能力不盲目重试。
- 付费/Build 提交不确定：先对账，禁止重复提交；已确认失败只从最近可信阶段恢复，并重新核价与匹配当前授权。
- 状态读取失败与制作失败分开；记录真实活动/最后可信状态，不假装仍在运行。失败主界面说明保留结果、已尝试恢复、当前实际选择，不默认要求技术 Retry。
- 记录首版耗时、各阶段活动时间/等待人/外部等待、模型轮次、修复轮次、人工打断原因、Provider 请求/对账、工程介入。没有当前测量，不承诺具体分钟 SLA。不记录原始凭证或敏感模型输出。

## 总体验收

普通支持范围的确定性场景：方案确认至首版人工操作为 0；关闭页面/重启可恢复；工程介入为 0；没有重复付费或重复 Build；输出在不放宽硬约束的前提下满足基本质量。必要异常问询必须具体说明为什么系统不能处理，不让用户理解技术阶段。

测试按风险扩展已有 integration/contract，优先保证幂等、授权/fingerprint、崩溃恢复、Rights/Match、媒体编排和质量回归；使用 fixture/fake Provider 与页面检查，不调用付费 AI，不运行真实 Build/完整 E2E。真实自主性和可看质量验收需用户另行启动，确定性测试不能判真实 E2E PASS。

必须解决或明确延期的前置依赖：持久调度原子性、逐请求批准到方案范围授权的策略契约、可靠语义/声音分析能力。仅完成后端自动串行和去掉按钮不足以宣称整体完成。按 1→2→3→4→5→6 分阶段交付，每阶段 root cause → minimal fix → targeted verification，不同时重构全系统。
