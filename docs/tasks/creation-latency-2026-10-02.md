## 1. 两个并列目标与成功边界

1. **自动获得足够合适的素材。** 优先复用和搜索；仍有真实缺口时，对允许生成且静态图能满足的视觉 Need，复用已有 AI 生图能力补位，避免长期卡在素材阶段。
2. **缩短素材准备耗时。** 减少无关搜索、重复观察、偏好误拒、报告故障及无变化重试。不能只减少调用却仍缺素材，也不能靠放松必要检查制造提速。

目标流程为正式 Planning 的 MaterialPlan / Need → 复用及 Library-first → 有界搜索与小批观察 → 按原因接续/补证/生图补位 → 普通素材准入 → MATERIAL_READY，或如实保留缺口并停止。全程共用累计边界，足够正式合格覆盖后停止，不追求每张素材完美。

当前导演语言、必要表达和事实/权利/技术/匹配检查保留，不要求每张素材满足全部风格偏好。完整视频的 Authoring、Hypit Build、成片审阅与跨内容风格验收后置，不因本次素材验收通过而认领完成。

本作品已有 10 元、仅真实缺口的授权保留，不重复询问，不扩服务或费用；本轮不使用它。未来独立素材验收的具体输入及授权绑定须适用，不能将原作品预算转授其他委托。停止条件、剩余额度与未知执行必须如实说明，不清零绕过。

## 3. v0.4 作品要求、风格与素材处理（历史范围）

### 3.1 要求按来源区分，保持现有责任

| 要求 | 处理 |
|---|---|
| 用户明确硬要求、事实/身份、隐私、权利与费用 | 不自动放宽；证据不足先寻找合规替代，确需用户独有信息或改变委托才集中询问 |
| 必要内容和表达 | 文案、论点、关键动作或事实证明有实际承担位置；不能以泛化配图冒充真实经历或删必要内容来提速 |
| 当前 Mode 的稳定表达要求 | 从现有 Mode 取得来源和适用范围，由 Planning / Production 在本作品落实；允许单镜头变化，整片仍保持导演语言 |
| 一般偏好与示意细节 | 用于排序、选优或可执行改善，在确认的范围内可取舍，不单独阻断全部候选 |
| 来源不明或冲突 | 定位用户要求、Mode 或模型临时建议；不随意升级硬条件、不静默放宽明确限制 |

Material 负责供应、观察、适用与权利证据；Planning / Production 负责导演判断、表达替代与编排；Hypit 执行制作。Quality 检查实际输出。无需新增 Director、风格平台或业务主链。

本作品在原方案中用简短的“要求—实际安排—核验证据”说明风格如何落地：

| 项目 | 应落实的安排与验收证据 |
|---|---|
| 选材 | 画面用途、主体/取片、允许替代；核对实际使用画面与组合，而非只读搜索词 |
| 旁白 | 当前 Mode 支持的声音身份、语速/语气与节奏；实际试听并核对完整性、字幕时序，不仅检查 TTS 参数 |
| BGM | 适合本内容的音乐选择、进入退出和与旁白的音量关系；检查实际听感和混音 |
| 字幕 | 当前 Mode 的可执行样式、布局及节奏；检查成片可读性和同步，不只检查工程字段 |
| 剪辑 | 镜头长度、转场、运动与叙事节奏的具体安排；检查实际成片是否体现当前导演语言 |

本轮正常样本应覆盖上述五项，不靠省去声音或字幕规避链路验证。具体形式依现有 Mode 和确认方案确定；若当前 Mode 明确排除某项，确认前说明冲突并由用户决定，不能擅改 Mode 或把未覆盖项记为通过。

风格核对并入已有 Planning、素材观察/组合、Production 和 Quality，不新增全套独立模型复审。仅当出现具体缺口时补充必要证据。多次替代后检查整片是否持续偏离；不逐素材追求所有风格指标满分，也不以“后期会调色/裁切”认领未执行效果。

### 3.2 对不同失败采用不同处理

| 分类 | 判断依据与系统动作 | 禁止的替代做法 |
|---|---|---|
| 真正不适合本用途 | 主体/动作/表达实际不符，淘汰该关联；连续失败调整查询、来源或授权范围内的表达 | 把素材对一个场景的不适合复制成所有场景的否定 |
| 证据不足 | 无法看到附件、覆盖不足或必要条件未知，针对性补看/补证，或换合规候选 | 直接当作 unsuitable；未见即断言不存在 |
| 疑似模型误判 | 实际帧与报告矛盾、遗漏关键区间等具体争议；利用有效原证据或针对性新证据有限复核 | 仅因为结果不满意就反复问同一模型，直到得到 PASS |
| 一般偏好差异 | 核心用途成立，差异落在允许取舍范围；记录偏差并按整片效果使用/改善 | 把色调、背景示意等全部提升为硬门禁 |
| 调用/报告故障 | 区分明确未执行、结果未知、结构错误；未知先对账，已成功结果复用，报告有限修复 | 将技术故障记为素材不适合；无变化重提或重新购买 |

候选先按用途与已有证据关联，减少全部 Need 与全部素材机械交叉送审。文本只帮助提名/排序，不替代真实画面；描述不全或语言不同的潜在正确候选保留有界探索机会。批次按当前作品需要设置，不建立通用召回平台。

每项已有足够正式合格覆盖且能组成确认方案时停止无目的选优；不因软偏好未满分继续搜索。连续负面结果必须根据原因换查询或处理策略，有新增信息才重试；补看、报告修复和补料各有明确上限，沿用已有效上限，仅在有证据时调整。数值由工程针对固定案例提出并随本次策略记录，不另设阈值治理项目。

限额耗尽时保留结果、明确缺口；这是可解释的停止，不是本轮验收成功。系统可处理的候选问题先由系统处理，不变成强制用户逐素材审核。

### 3.3 本轮适配准入边界已确定

- 已观察的可用视频区间：仅在现有合同允许、其他硬条件与 Rights 均满足时准入；记录原素材身份、Need、观察范围及实际取片约束，Production 的使用不能越界，导出后仍做必要检查。
- 原本已合格素材的裁切、字幕、混音等表达适配：由 Production 使用已有能力完成，实际结果需保留主体/表达并通过 Quality；不因输入合格而跳过成片检查。
- **本轮不新增“裁切消除硬冲突后准入”。** 需要该新能力才能通过的候选保留缺口并寻找合规替代；不安排对应 ADR/衍生资产平台研发，也不再列为本轮待用户决定事项。
- 裁切不能代替授权判断。少量抽帧未见 Logo/人物不能证明整段不存在；不能将 partial 一律变成合格，也不能将其一律淘汰，应按现有可验证使用范围处理。

## 4. v0.4 最小实施包与真实依赖（历史已批准软件范围）

保留原三步路线：①减少重复工作与无效等待；②改善方案可制作性、素材适配和审核；③长作品组织与局部重做。**当前只推进前两步，第三步延期。** 以下沿用 1A/1B/2A/2B；Quality 是原主链的收口，不新增独立平台或全套模型复审。

### 1A：最少计量与可解释重试

- **目标：** 知道素材何时够用、每次派发为何发生、主要时间花在执行还是等待；将制作与工程诊断分开。
- **已有能力：** 阶段时间、网关请求身份、operation_timings、共享批次、终态释放及恢复记录。
- **实际缺口：** 同 digest 明确失败重派覆盖 run_id，登记条数不等于实际派发数；多层重试各自有界，但累计成本不够直观。工程介入与环境等待影响本次经过时间。
- **改动边界：** 在现有记录中保留每次真实派发及其原因、前后策略/证据变化、终态和产物校验结果；区分首次调用、报告修复、语义补证、补料、轮询。按阶段呈现累计轮次和停止原因，不建立通用遥测或重试平台。未知执行先对账；确定性输入冲突不原样重跑；短暂调用故障仍可按现有上限重试。不同层不因重入重置各自有效上限。
- **同阶段累计额度与停止条件（本次批准补清）：** 沿现有 Delivery 的 Creation 委托记录，在派发前累计预占准备/规划、素材、编排、审片四类阶段的新网关调用，以及素材检索适配调用、本地声音观察、生成报价和新提交；首次执行、补证、报告修复及明确失败重派均计入，轮询/终态清理/有效产物读取不计入。各层原上限继续同时生效，总额由原三次失败、单 Need 九项探索、有限补料、一次报告修复、三轮观察及两轮质量修正的最大组合推导，并在首次使用时保存；恢复、子流程重入、自动修复副本和显式 Retry 不清零。达到累计上限、该阶段已有充分合格结果、原局部上限耗尽，或无新增证据/策略可解决已知问题时，不再派发对应新工作。未知提交优先对账和释放终态，不因额度耗尽停止观察；有效文件/素材/报告保留，耗尽记录为未交付。正式实现数值及推导、覆盖范围与验证证据在同文实施记录更新，不另建重试平台。
- **依赖：** 原执行入口与身份，不依赖 1B/2A/2B 全部完成。
- **验收：** 固定失败/恢复案例中实际派发逐条可核对；轮询不计新调用，成功产物不重算，未知请求不重提。休眠/网络/人工等待单列，未知不强行扣除；内部时间不重复相加。只证明网关派发时，不能冒充 Provider 内部 API 调用或账单。

### 1B：准备、规划与编排的确定性工作不反复返工

- **目标：** 让模型负责创作判断，减少字段整理、帧数推导、文件缺失等可确定问题引发的整轮重做。
- **已有能力：** 已确认文案复用、冻结输入、Truth 证据绑定、隔离编排、缺文件有限补齐、精确取片错误反馈及 checkpoint。
- **实际缺口：** 确认文案字段混入非朗读说明导致合法整理与冻结检查冲突；已修正的编排落盘/依赖问题尚未证明稳定自主通过。仅反馈越界错误仍可能让模型重复推导已知区间。
- **改动边界：** 在确认前明确逐字稿与说明的各自位置并验证，确认后不能自动删改正文。复用已确认且未变化的文案/分镜和确定性字段；结构错误局部修复后复验整体合同。Truth 沿现有依赖身份复用，相关变化正确失效并保留跨段关系检查，不建事实平台。向原 Authoring 提供已知的素材区间、时钟与可用整数帧界，由确定性校验兜底，不静默夹取越界值。核实已有逐文件保存及白名单依赖补齐，调用成功必须同时满足实际文件/合同校验；不新增执行权限。
- **依赖：** 相应输入、素材/语音的有效证据与当前安装合同；不要求先完成全部计量设施。
- **验收：** 本轮混杂文案案例在确认前暴露或正确分离，冻结正文不变；缺文件/依赖冲突有明确局部处理；有效规划、Truth、素材及旁白不因编排失败重做。纯复用的判断保持等价；确认字段 Bug 修正单独说明行为变化。沿已有回归验证边界与恢复，不以新增测试数量验收。

### 2B：更快获得足够合适的素材

- **目标：** 减少无关候选进入视觉观察，确保失败后的策略改变真正作用于检索，正式覆盖后及时停止。
- **已有能力：** Library-first、Provider 查询、related-first-v4、小批有界接续、同素材共享观察、独立 Need 结论、可用区间与正式 Gate；BGM 显式补料查询优先已修正。
- **实际缺口：** 长分镜与风格词直接形成复杂查询；实际 Provider 限制与首查询优先影响召回；没有语义描述时排序优势不足。已有查询修正不证明所有来源恢复都有效。
- **改动边界：** 检索短语优先表达可见主体、用途和必要动作，使用已有可信元数据辅助提名；Mode 中适合检索的视觉线索有界加入，其余偏好留给排序及整片编排，不删除必要表达或稳定导演语言。Provider 长度/语法处理在适配边界核对官方契约，不把 Provider schema 放进 Domain；不能靠盲截断丢掉主体或硬条件。记录实际发送的查询；连续失败依据原因换查询、来源或当前授权内的处理策略。缺少 caption/tags 时继续有界探索，不强制所有候选新增一轮模型描述。复用现有共享观察、正式区间、Rights 和覆盖停止，不新建缓存或召回平台。
- **依赖：** 当前 Need 的用途/要求分级及真实查询证据；可以先独立改善，不等待 2A/Quality 完成。
- **验收：** 本轮长查询和“策略变了但实际查询未变”案例得到明确处理；固定候选验证相关性改善不会误杀描述缺失但正确的素材。五类失败仍按 §3.2 区分；已够用停止，候选耗尽/预算耗尽保留缺口。真实验收同时报告素材齐备时间与无效调用；调用少但素材仍不足不算成功。

### 2A：必要表达在初次 Authoring 中完成，Quality 以实际证据收口

- **目标：** 被确认的必要表达有明确承担位置并实际出现；当前 Mode 影响选材、旁白、BGM、字幕、剪辑，交付基本可看首版。
- **已有能力：** 冻结 Mode/分镜、导演取舍、原生 Hypit 编排、真实语音时序、字幕/混音路径、编码输出取帧、声音测量、分组 Quality 和有限表现修复。
- **实际缺口：** B-roll 替代后，关键文字/图形表达未落实；字幕分段与节拍没有随语音实际协调；局部采样承担过多全片判断，存在误判/误通过；报告缺失使最终停止。当前局部修复不能自由改文字、时序或依赖。
- **改动边界与依赖：** 按以下两个独立目标推进，均归入原包；共享文件写入/重试修正归 1B/1A，不重复建设。

**2A 的初次编排目标：**

1. 在现有方案与 SCENES 中保留“必要表达—由谁承担—实际安排—验收证据”的简短对应。素材负责背景时，图形/文字必须明确承担剩余语义；不是每句都要求精确库存画面，也不新增所有场景必经的模型确认。
2. 确认方案前核对当前安装 Hypit 与 Authoring 支持的文字/图形组合；未核实能力不能承诺。表达意图与可编辑执行参数分开：完整批准文字、事实与硬时长不变；允许调整的镜头/字幕节奏由确认范围决定。若时长与完整内容不能兼容，应呈现具体取舍，不能擅自缩短、拉伸语音或删内容。
3. 素材和语音就绪后，在初次 Authoring 中使用实际语音时序安排字幕分段、可读布局、镜头节拍与结尾留白；分段保持完整文字及顺序。风格默认表现复用已有 Mode 的能力，允许内容相关变化，不采用统一片头/镜头数强行套模板。
4. 正式 Build 前用现有静态检查确认必要承担项没有漏编排、取片与时序合法、文字及音轨完整。工程字段存在只能证明安排存在，真正可看仍要看编码输出；不新增 Build 前全片模型审核。

**初次编排验收：** 固定本轮关系缺失、长字幕、语音/节拍错配案例验证实际安排与受保护输入；用当前安装合同验证支持程度。真实首版能看到“一项突出、其余保留”的关系，小屏文字可读、语音完整、节拍有意义；不靠精准手部素材、重购已有旁白或删除声音过关。字幕分段在初次编排使用已核实的识别词边界，不能认领为 Quality 局部返修权限。

**2A 的 Quality 目标（关联 1B/2B）：**

1. 在原 Quality 内区分局部证据与整片结论。单组帧核对实际可见主体、字幕、构图及对应时间的表达；整片必要表达/Mode 结论由已有各组证据与节拍覆盖汇总。复用同次观察，优先确定性汇总；不额外加一整轮全片模型复审，不让每个局部批次重新判断全部未见节拍。
2. 无字幕的时点先与安排核对：本就应留白不产生字幕缺证；该出现却未出现属于缺陷。没有覆盖关键动作的采样不证明动作不存在，字段自洽也不证明模型看对；确认可见反证后再定向处理。
3. **最小定向补证：** 仅在现有采样未覆盖必要表达或有具体画面争议时，针对相应节拍/字幕时点，从同一输出补取实际帧并复核受影响项，沿现有总轮次限制；不对所有素材/全片重复观察、不修改视频、不生成新素材。同证据同策略无法解决的 unknown 不原样循环。若动态动作仅靠帧仍不能证明，保留明确缺口，不承诺逐帧/全视频理解。本次已完成同输出、有限新时点与报告 checkpoint 接续的软件修改；实际模型效果仍待验收。
4. 已核实最后会话长度截断与报告缺失；本次修正要求先写文件后简短回复，优先验证已有报告，再有限局部恢复。模型执行终态、实际报告存在、报告身份/结构合格和语义可信分别校验。已有有效视觉结论保留；仅结构或文件故障不自动重审素材/重做影片。优先复用已有写入路径；若需要更换输出传输方式或增加权限，列具体边界另作决定，不预先承诺支持。局部报告修复复用同会话原证据，不重发全套附件与正文；缩短上下文是否改善真实稳定性仍待验证。
5. 明确缺陷责任与当前可修范围。样式/位置、gain/fade 等沿现有表现修复；缺少必要图形、需拆字幕/重排节拍则记录初次编排缺陷，**本轮不扩大 Quality 局部修复合同**。不能错误标为换素材，让 Material 为编排遗漏补买。此类失败进入诊断，不能认领首版交付成功。

**Quality 验收：** 固定本轮桌面/墙面、虚构字幕底色、未见节拍、无字幕留白、报告缺失案例，先确定性验证证据覆盖、分类和恢复，再实际审阅编码帧验证模型判断。声音告警与真实试听分开；不能伪造听审。报告稳定落盘不等于语义通过，抽帧通过不等于完整感知通过。最终由正常首版审阅确认音画可看，用户接受/Selected Output 保持原职责。

### 4.1 实施顺序与停止边界

1. **已有能力生效和最小确定性修正：** 1A 请求记录、1B 确认稿/文件合同与 2B 查询修正按真实依赖分别推进；不等待完整基础设施。已有修复先核实，避免重复开发。
2. **表达落地与审片收口：** 2A 初次编排和 Quality 可以分别用固定证据验证，最终在同一正式主链汇合。定向补证需要输出时间绑定/报告合同支持；这些未完成前不宣称已支持可信复核。
3. **冻结版本后的单主题验收：** 软件回归及能力核实通过后，才按 §5 准备一份具体可运行委托。三步路线的第三步继续延期。

未知执行继续对账；确定性输入冲突先修输入；瞬时故障按原上限；缺证带着新证据补查；已有足够合格覆盖即停。每次恢复要有原因、变化和预期结果，不为耗尽上限而运行。无法在当前合同处理的缺陷明确停止，不新增权限或扩展费用来硬推。

## 5. v0.4 样本、调试方式与真实验收（历史范围）

### 5.1 固定证据与正常主题

诊断继续使用已确认主题“把待办清单缩减为今天最重要的一件事”、本轮真实错误与原始失败记录，不换简单模板挑选成功。少量固定案例优先扩展既有高价值测试：长查询、实际补料词未变化、第五候选接续、描述缺失、混杂文案、文件缺失、越界取片、必要图形缺失、字幕/节拍错配，以及 §4 的审片反例。案例按风险合并，不机械一项一测试。

下一次正式验收仍用同一正常主题与当前 Creator/Mode，由原 Easel 入口形成版本明确的文案、分镜、声音与规格；先核对能力和授权，不预设全新委托可继承旧作品预算。允许修正已证实的系统问题，不能删除难点、必要声音或表达以通过。保留旧失败，新的独立验收记录不能覆盖它；不迁移旧作品数据。

### 5.2 将诊断运行与验收运行分开

- **诊断：** 使用保留的报告/素材/帧及确定性回放定位问题；可以在批准后修代码，但不据此宣称无需工程救场。需要模型、服务或 Build 时单独遵守实际授权范围。审阅截图等只放 Attempt 工程外，不污染执行指纹。
- **验收：** 启动前固定代码/策略版本、当前安装合同、委托和预算，确认执行环境可持续运行。临时防闲置休眠不保证防合盖休眠；环境中断按事实记录，不增加系统电源管理平台。
- 运行中需要代码修正、手工补料、工程许可核实或阶段救场，即标记该次自主性失败；保留可用成果并转入诊断。不能把救场后的结果倒算成原自主成功。正常最终首版审阅不属于工程救场。
- 真实运行不用于无限探索 Bug；确定性问题先在局部解决并做必要回归，再开始下一次验收。测试通过不能替代实际视频证据。

### 5.3 必须同时满足的完成标准

| 维度 | 通过条件 | 不足以通过的证据 |
|---|---|---|
| 素材效率 | 视觉/旁白/BGM 正式齐备，已有足够覆盖即停；无关、重复和无变化调用的改进有可核对依据 | 调用下降但缺素材；拿候选数代替正式覆盖 |
| 表达与风格 | 必要关系真实出现；选材、旁白、BGM、字幕、剪辑体现当前 Mode；内容完整，表达允许随主题变化 | 场景 ID、文件/哈希或 Mode 参数存在 |
| 审片可信度 | 结论有相应时间的实际输出证据，误拒/误通过分开记录；缺证不伪造 PASS；报告保存可靠 | JSON 合格、软件回放通过、相同采样反复得到同结论 |
| 基本可看 | 实际视频小屏阅读可行，声音完整且混音可听，节拍协调；经过正常首版审阅 | MP4 可播放、技术 QC pass、信号告警直接等同听感 |
| 自主性与边界 | 正常确认后无工程救场交付可审阅首版；Truth/Rights/预算、未知执行对账、输出身份保持 | 人工改数据/产物、代审核或后台救场后记为成功 |

单主题成功仅证明该链路可行，不证明跨内容风格一致性。后者仍是 V1 核心验收，单独安排，不扩大本轮矩阵。

### 5.4 计量与正确性证明

记录确认至素材齐备、首个导出、首版可审阅的时间及各阶段经过时间；素材唯一数量、Need 关联数量、正式派发/补证/报告修复/补料次数、失败原因、人工介入、已知费用与未知部分。Preparation、Planning、结构修正、Truth 纳入测量，不只计 Material。网关请求、内部 API 调用、预估与账单区分；同请求轮询不计提交、失败重派不能覆盖历史，重叠时间不重复相加。

纯复用优化验证同输入与有效证据下判断等价，并保护依赖变化失效；经批准的查询/审核策略变化用固定真实案例解释预期差异，不能要求保持原错误结论。现有局部恢复仍核验依赖与身份，不引入延期的长作品局部重做。

离线对照可以证明具体重复减少、正确覆盖和错误处理；真实运行证明成片与自主性。没有同条件真实基线时只报告测得数据，不声称整片提速比例，也不以旧失败运行的总时长作严格对照。不为制造对照数字额外付费重跑旧链路。

### 12.2 目标流程与切换策略

```text
正式 Planning 的 MaterialPlan / Need + 适用委托授权
→ 校验身份、硬要求、生成适用性及剩余累计空间
→ 当前有效素材 / Library-first
→ 缺口对应的短 query 与可获取来源，小批提名和实际观察
→ 逐 Need 匹配、Rights 与 Readiness 重算
   ├─ 足够正式合格覆盖：MATERIAL_READY，素材验收停止
   ├─ 有合适的未观察候选：接续小批观察
   ├─ 检索收益不足：改变查询或来源；符合条件时转已有 AI 生图
   ├─ 证据不足：仅补受影响的必要证据
   └─ 报告/调用故障、未知执行或边界耗尽：修复/对账或保留缺口停止
生图 → 原 MaterialAsset intake → 观察 / Rights / Match → 同一 Readiness
```

| 当前情况 | 下一动作与依据 | 不能做的事 |
|---|---|---|
| 所有 required Need 正式覆盖 | 立即停止供料，保存 Bundle/Readiness 与计量 | 为凑候选数继续搜索或生成；将 optional 不足误记为 required 缺口 |
| 尚有与缺口相关、未观察的候选 | 接续小批；每批后重新核对覆盖，共享解码但保持逐 Need 结论 | 只因候选总量足够就停止；同资产对无关 Need 全量交叉审核 |
| 候选实际内容错配或重复率高 | 根据失败原因选择有实质变化的替代/拓宽 query；当前来源不支持需求或新增收益不足时换可获取来源 | 重复同义词、每次全量打所有 Provider；改变硬约束来制造命中 |
| 证据不足但存在可验证的关键疑点 | 在现有证据能力内对受影响 Need/素材定向补证，有新证据才重判 | 将 unknown 当不适合；无限补看或自动转生图 |
| 只有一般偏好差异 | 按现有可取舍边界进行正式匹配和排序，保留导演语言 | 把色调/桌面色等偏好自动升级为硬门槛；删除核心表达 |
| 报告未保存、合同矛盾、调用故障 | 接续保存、一次既有局部合同修复或核对原运行；持续失败如实停止 | 将报告故障标为“搜不到”并触发生图，扩大搜索掩盖故障 |
| 有真实视觉缺口且继续检索收益不足 | 在下面条件全部满足时转已有生图入口；否则选择仍有依据的补料或停止 | 要求耗尽所有来源才生成，或只凭搜索慢就生成 |

**生图切换条件：** 已优先核对可复用资产及进行有界、与需求相关的搜索/观察；有效结果能证明缺口，而非仅存在坏报告；当前 Need 允许生成且静态图能承担其必要表达；未有待对账或可复用的生成结果；原服务/费用授权有效、核价明确，且剩余空间足以提交、获取、观察和正式准入。已有合适未观察候选时通常先看小批；如建议转生图，应记录为什么下一批检索的预期收益低、静态图为何适用，不机械耗尽候选或全 Provider。

**时间与额度安排（拟定策略，不伪造时延保证）：** 每个真实缺口开始及每批结束时记录剩余累计调用、费用可用额和已用时间。为可生图缺口预留“核价/提交/接收恢复 + 技术检查/内容观察 + 必要报告修复”的调用容量及已核价费用；无法估价时不提交。根据同服务已有耗时或保守估计安排生成和验证时间窗口，估计无依据则标未知，不能虚构一定更快。下一轮搜索将侵占预留空间且收益不足时，优先评估生图；不适用或空间不足则保留缺口停止。等待中的外部请求按原身份对账，超时不授权重复购买。具体批量/时间窗口沿已有局部上限与实测制定，不在本轮编造新的硬分钟数或增加总额。

搜索、补证、报告修复、生成报价与提交共用原素材累计边界；局部上限先到先停。费用账与调用账分开，时间预留不增加任何额度。来源切换、恢复、Need 修订均不能重获全部额度。

#### 12.10.3 收敛后的设计决定：围绕缺口完成一次有效动作

本次修订替代此前仅列局部修复的建议，已获软件实施批准。要解决的是各模块各自“做完”、整体却迟迟不齐备：保留现有 Delivery Owner，把素材步骤收敛为“逐 Need 看缺口 → 选择并持久保存一个有限动作 → 获取新证据 → 重算正式覆盖”。不另建调度器、检索平台、审核 Agent 群或素材主链。

必须同时落地六项，不能只缩小批量或继续补提示：

1. **审核要求只解释一次。** 必要表达、明确禁令、可取舍偏好及后期职责形成绑定冻结输入的审核合同；每次观察使用同一合同。
2. **候选有明确服务对象。** 保存搜索/生成的目标 Need 和来源，先为该缺口观察；跨 Need 复用必须有相关依据。
3. **观察只执行一小批后返回。** 不在一次操作里审满池；下一动作由缺口原因决定。
4. **模型只交观察判断。** 系统接收原 run 的紧凑结果并负责身份、校验、保存；不再让观察模型写文件、复制 SHA。
5. **已知不满足、证据不足、权利待解、执行故障分流。** 不再由笼统 partial 或全局观察 COMPLETE 决定一切，也不再要求所有候选 unsuitable 才允许生图。
6. **音频可验证是恢复前置。** 本次要补齐旁白/BGM 的证据闭环；不能只修视觉后再遇到同一音频阻塞。

正式入口保持：

```text
当前正式 MaterialPlan / Need + 冻结上下文 + 授权及累计账本
→ 要求合同与 required 音频供给/验证能力检查
→ 当前有效成果 / Library-first
→ 按 Need 投影真实缺口
→ 一个有身份、有边界的动作：取候选 / 观察 / 换 query或来源 / 补证 / 生成
→ 保存成果、重算 Rights / Match / Readiness
→ 已齐备则 MATERIAL_READY；未齐备则根据新证据决定下一动作
→ 没有合法且有新证据机会的动作，保存明确缺口停止
```

“停止”是诚实边界，不是交付成功；本方案仍以足够正式合格覆盖为目标。

#### 12.10.4 要求与观察合同：减少反复解释，不假装程序会看图

**要求合同沿现有 Planning 产生。** 保持 MaterialNeed 及冻结原文不变，在 Attempt 内保存一个派生审核合同，绑定 Plan/Need/Brief/Mode 的摘要。新 Planning 提示同轮交付 `MATERIAL_REQUIREMENTS.json`，存在即严格验证、缓存；为兼容既有 Planning 产物，缺少派生文件时沿观察入口仅编译一次，歧义阻止观察。当前作品复用已有正式输入，不重跑创作方案、不手改冻结文件。

每条要求保留短 ID、类别、适用媒体、来源位置及原文摘录：

| 类别 | 示例及处理 |
|---|---|
| 必要表达/明确禁令 | 主体必须存在、清单一项圈出其余未删除、真实身份/事件证据、必要源动作、用户明确禁止项；不满足即内容缺口 |
| 已明确允许取舍的偏好 | 当前 preferred_visual_details 中的浅景深、桌面材质等；只记偏差并排序，不因在 intent 重复出现升级为硬门槛 |
| 后期承担项 | 静图上的微推、字幕出现、剪辑节奏；不要求源图片已完成，不承诺后期补出缺失主体 |
| 尚有歧义 | 对核心表达/偏好归属无法可靠解释；保留原要求，由原 Planning/Director 有界解释，不静默删去或改软 |

Mode 中明确必须遵守的语言不能全部降为偏好。程序能核对原文引用、显式约束、覆盖和冲突，不能证明自然语言分类一定正确；分类质量也要验收。有界解释后仍有歧义，则该 Need 保留合同阻塞；不能遗漏条款后判全部满足，也不能每次换候选都重新解释。合同不会赋予 Material Layer 改写创作意图的权力；如确需改变原意，仍走正式版本化修订。

**一次观察同时产出共用事实和必要项判定。** 每个实际附件/帧的可见描述、logo/text 等观察事实只描述一次；每个被提名 Need 的必要项给 met / not_met / unknown 和简短实际依据。必要项全部满足才支持适用，偏好单列；拒绝必须指出未满足的必要项，不能再以自由总结的 partial 隐藏原因。视频仍遵守采样与可用区间合同，不把一帧合格推断成全片合格。

观察同时判断事实和要求，不额外先给全池跑 caption；超容量时按下述规则拆分，不能承诺任意 Need 只有一次调用。已保存的字节/预览绑定事实可作新 Need 提名线索；旧 A 的适用结论不能直接给 B，新要求所需细节没有证据才补观察。新增派生合同不自动使旧报告全部失效：当前 Need/字节/用途未变且无具名反证的既有正式准入，按原合同、原身份和原报告继续有效，不伪造新版逐条答案；仅对新增关联、具名误拒或必要新证据缺口使用新合同。程序根据模型提供的逐项证据形成现有正式报告和 Match 输入，不用关键词、源标题或规则推测画面。模型仍可能看错，后述真实语义样本是必须的验收门。

**撤掉观察模型的机械文件交付。** 已只读核实本机 OpenClaw 2026.9.4：`principal-CweFVZNq.mjs` 的 `agent.wait({runId})` 返回该运行的 stopReason、terminalReceipt、terminalReply；`run-wait-DIjoJjlE.mjs` 已能读取 terminalReply.text。Easel 的 `run_delivery_agent` 当前成功时返回空 stdout，故要补一条窄的接收路径，不能假定现成可解析返回值。

沿现有 agent.wait、runId、请求账本、幂等和对账，持久保存可信终态结果及绑定上下文，再由系统组装 schema/hash 并原子保存正式观察。模型只返回短序号、事实和判断，不返回文件路径、SHA 或输入原文。安装版终态文本最多 4096 个 UTF-16 单位，拟设观察协议上限 3000，并给各字段限长；按帧数、条款数与有关 Need 数计算最坏输出后派发，不能继续把四个长报告塞入同一返回。缩到单 Need 仍超限时，在原累计边界内按条款/帧组拆分、完整汇合后才准入，或派发前报告容量不足；不能省略要求，也不能把网关截断当作普通模型错误无限修复。

缺失结果、length、截断、未知 run、错误序号、漏项和矛盾均是交付失败；不能读 session 最新回复冒充原 run，也不把旧错绑文件改 hash。成功结果接收中断只恢复保存；同一可完整解析的响应中，能独立验证的有效子项先落盘，仅对失败子项做原一次修复；全响应截断不猜测抢救。先用现网关路径，不同时开发另一套提交工具或直接模型客户端。接口兼容性若未通过，停止本项交付，不用真实全流程试错。

此窄协议优先用于视觉观察及简短补料结果。完整 Planning 文件不挤入 4096 字符返回，保留现有文件入口和 §12.9 修复；当前已有效 Plan 直接复用。

#### 12.10.5 候选、接续和生图：同一个 Owner 的决策表

**保留已存在的候选线索。** `SupplyCandidate.need_id`、Provider 元数据和返回排名已经存在。在现有 acquisition / recovery 记录保留 Need revision、实际 wire query、来源、排名、候选身份与去重后资产 SHA 映射。字节去重合并来源线索，不丢失第二个 Need 的检索关联；元数据不冒充画面或 Rights 证据。

初始执行配置建议每 Need 提名 1～2 个有依据候选，同一资产仅合并有依据的少量 Need；无来源、无语义的本地文件在整个调度轮只取一个有限探索批，不能对每个 Need 复制同一批。该配置是待回放验证的起点，输出体量超限时继续缩小，不能为少调用省略必要证据。

`observe_visual_materials` 每次只消费当前冻结批次，完成后保存有效项、重算 Gate 并返回 Owner；“本批交付完成”不再表示候选耗尽。所有下一动作复用原 Owner 与累计账本，不让观察、恢复、生成各自开启循环。

| 逐 Need 的当前证据 | 下一动作 | 判定边界 |
|---|---|---|
| 已有足够 qualified 覆盖 | 结束该 Need 供料 | 不继续追求更多候选或更完美风格 |
| 有明确相关未审候选，本批得到新的必要项证据 | 再审一小批 | 候选线索需真实存在，不因池非空就继续 |
| 必要主体/动作反复错配 | 使用已编译的替代/拓宽 query | 主体、必要动作、场景优先；主 query 不自动附加 style |
| query 合适但该来源空、重复或持续低收益 | 换一个现有可获取来源 | 收益绑定当前 Need/query，不能由其他 Need 的拒绝降权整个 Provider |
| partial，但已明确缺少某必要项 | 视为真实内容缺口，评估剩余候选、检索或合法生图 | 不需把原报告改成 unsuitable；可用视频区间仍沿既有合同处理 |
| 仅偏好/后期差异 | 正常排序/匹配，必要时定向纠正有证据的误拒 | 不删除核心表达；旧正面和明确硬冲突不全量重评 |
| 某候选必要细节 unknown | 有可行方法才定向补证一次，否则挂起该候选 | unknown 不算已证明搜索失败；一个 unknown 也不能永久锁住该 Need 的其他合法路径 |
| 内容适合但 Rights 未明 | 核对该资产的许可/署名证据 | 不靠重复观察或已付费自动准入，不把缺权利证据标成内容错配 |
| 报告/调用故障 | 接收/修复原结果或对账 | 不扩大搜索或用生图掩盖故障；全局未知提交继续阻止新副作用 |
| 无合法有收益的下一动作/边界不足 | 保存具体缺口停止 | 不清计数、不换 Attempt 绕过 |

**查询变体预先有限编译，按需使用。** 主查询、替代、拓宽沿当前 Compiler/Planning 合同保留；不能每次切换都再让模型写长篇补料计划。优先用已编译变体，只有出现原变体未覆盖的新拒绝原因时才允许原有界补料编译。缓存以真实 query、过滤条件、分页/continuation、Provider 及输入证据识别重复，不能只比较上层提示不同。旁白不再到通用图库搜“朗读指令”，BGM 查询只用音乐用途及必要声音特征。

**生图不以全池穷尽为前提。** 当前资产/Library 已核对，至少一轮有意义的真实检索成功返回空结果或获得有效低收益证据，仍有缺口且没有更有依据的待审候选时，即可评估生成。必须同时满足 Need/Brief 内容许可、静态可替代性、服务范围、当前报价/剩余额度、无未知或可复用生成请求，并预留结果验证空间。硬缺失的 partial 是可用的缺口依据；unknown/Rights/系统故障本身不是切换依据。候选局部挂起后，只能以其他独立有效证据支持替代供料。

生成先完成请求绑定 Need 的技术/观察/Rights/Match 准入；仅在有具体相关线索时给其他 Need 使用。成功生成不触发旧池重新探索，不整片重生成；现有“一 Need 当前输入的首次生成”及幂等/费用边界保留，不自行扩大成无限抽图。生成结果确实不合格时保存原因，评估现有合法替代；无替代则失败，不擅自重购。

**进展与预算按 Need 跨批累计。** 进展是新增 qualified 覆盖、解决了必要项未知、或得到了能改变策略的新证据，不能把又写一份同类负面报告计为收益。同一策略小批没有带来必要项改善时，必须换有实质依据的策略或停止，不能自动再审同类一批。保留现有全局总额；在已有账本中累计候选关联、query、补证、修复、生成及耗时，池更新/来源切换/重启不归零。按全部剩余可生成 Need 估计生成及验证所需空间，未知价格先核价，不能只在最后检查剩 5 次调用。时间估计用具名实测，无法估计则标未知，不承诺固定分钟数。

失败身份包含素材/输入、模型或验证器、参数和规则版本。确定性失败无条件变化直接复用结果；临时错误最多一次有依据重试，报告合同仍最多一次修复，均不重置原累计边界。另行 Retry 不等于已有失败条件已经改变。

**修复三个目前的全局耦合。** 来源收益只取当前 Need/query 的有效结果；生成新资产不对全部 Need 默认送审；音频待证不重复抢占 Owner，也不因为剩余含音频就禁止视觉补料。单个候选阻塞可与其他 Need 的合法有限动作并存；若 required 能力已明确没有交付路径，应及时停止新增付费工作并报告能力缺口，不盲目把其余池做满。

#### 12.10.6 音频：本次必须闭合的交付前置

**更精确的事实。** 保存 ASR 的 95 个有效字符与冻结脚本去标点/空白后的 95 字完全相同，唯一低置信词“每”为 0.282。这是内容证据未达到当前规则，不是已经发现漏读。自动检测语言已为 zh，不能承诺只把 language=None 改成 zh 就解决。BGM 现有 At Rest 206.568 秒、41 窗，Music 最低 0.764、人声标签最高 0.104；现有规则判 unknown，没有达到 vocals_detected 的 0.2。音频分数不是校准概率，不能直接当作“有错字/有人声”的事实。

**旁白依次解决三个独立问题。**
